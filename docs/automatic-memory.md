# 自动长期记忆与 DSH 接入

用户已选择：从开启后的对话自动记住明确偏好、个人背景和持续事项，并在相关对话中自动交给当前配置的模型。个人信息可跨会话使用，项目内容仅在同项目使用，排除密码、密钥等秘密。当前实现、测试与发布状态统一见 [P79](ROADMAP.md#p79-auto-memory)，设计决定见 [ADR 0039](decisions/0039-automatic-memory.md)。

## 行为

Core 在已有聊天调用中提取最多 3 条候选，每条为当前用户输入中的 4–300 字原文；不额外启动模型调用或后台扫描。Provider 流式隔离保留标记 `NEXUS_META` 和最多 4 KiB 的严格 JSON，兼容标记独占一行、JSON 多行及元数据在正文前后出现；正文只暂存可能跨片的标记前缀。超长或未闭合对象没有可信正文边界时丢弃其剩余内容，不显示内部数据。候选不是已保存记录，Core 检查持续授权、来源、范围和排除规则后，才与模型结算一起落盘。失败、截断、停止或授权已撤销的模型交换不新增记忆；此前已保存的记录不会因后续工具失败而回滚。普通聊天不依赖设备在线或工具授权；文字和经现有聊天入口提交的语音共用逻辑。

偏好、背景以用户自述事实记录，持续事项以计划记录，均标记 `unverified`，不伪装成外部验证的事实；持续事项默认 90 天有效，可通过现有编辑接口调整。内容保留原文、来源 `chat:<turn_id>`、保存同意和策略版本。相同范围的相同原文不重复创建；已撤销或被替代的原文不会自动复活，已过期的持续事项可在用户再次陈述后重新保存。

开启前的聊天和原有手动记忆不会自动纳入。自动召回只处理已纳入自动使用范围、未撤销、未替代、未过期的条目；最多检查最近 1000 条，按中文双字片段／英文词的稀有度与长度排序。通用沟通偏好无匹配时最多保留两条，兴趣等主题偏好需匹配查询。个人记忆的 `project_id=null`，项目记忆仅进入同一个 `project_id` 的对话。手动选择记忆仍沿用原预览、摘要与逐轮外发同意，不被这个开关替代。

P88 本地实现进一步控制重复注入：同范围按 Unicode NFC、换行及首尾空白去重，保留否定、数值、大小写和内部空白；不删除旧条目、不做语义合并，撤销记录不自动复活。完整引用仍可在原接口查看，模型副本省略重复编号等元数据，保留内容、类型、来源、验证、时间和必要的范围／有效期；最多 8 条、完整引用合计 4 KiB，整个记忆消息最多 800 本地估算 token。实际发布状态见 [P88](ROADMAP.md#p88-context-efficiency)。

关闭后保留历史记录，停止后续自动提取和召回。关闭、纠正、撤销都会使已捕获的自动记忆上下文失效，包括普通历史、压缩摘要、结果解释和显式历史引用；尚未开始的旧请求会返回 `MEMORY_UNAVAILABLE`，重新发送即可按当前设置构建。已经外发的内容无法撤回，在途调用可能结束，但旧授权不再允许保存。重新开启可使用仍有效的自动记忆，不补提取关闭期间的聊天。

分类和是否值得长期记住仍依赖模型判断；原文核对不等于语义判断正确。Core 另行排除常见秘密标记、密钥格式、明确“不要记住”、代码块和 Markdown 引文，并拒绝含明确项目标记却声明为个人的候选。这些规则可能漏判或过度排除，不能承诺识别任意秘密或任意语言的所有引用。检索不使用向量服务，改写、同义表达或较旧信息可能未召回；已验证的真实样例和实际遗漏见P79，不能据此保证每条细节均提取或所有情境均正确。

## 后端接口

所有接口沿用 owner 登录、Origin 和写操作 CSRF 检查。模型、插件和 Node 没有开启持续同意的工具。新库与升级库均默认关闭，不能因安装新版本替用户同意。

`GET /api/v1/memories/policy` 返回 `policy`：`owner_id`、`enabled`、`revision`、`enabled_at`、`updated_at`。未设置时 `enabled=false, revision=0`。先读取当前版本，再 `PATCH /api/v1/memories/policy`：

```json
{
  "expected_revision": 0,
  "enabled": true,
  "consent_save": true,
  "consent_model": true
}
```

两项同意均为严格布尔值。关闭只需 `{"expected_revision":当前版本,"enabled":false}`。版本冲突返回 409；纠正或撤销自动记忆也会推进版本，因此发生冲突后需重新读取，不能盲重放开启请求。开启、关闭、上下文失效及具体自动保存均保留审计。`enabled_at` 用于拒绝提取此前已经排队的输入。

`GET /api/v1/memories` 沿用现有分页、`history` 和 `project_id`。条目新增：

| 字段 | 含义 |
| --- | --- |
| `auto_category` | `preference`、`background`、`ongoing`；null 表示原手动记忆 |
| `auto_policy_revision` | 自动纳入时的策略版本；手动纠正会保留其自动使用属性及来源版本 |

纠正仍用 `POST /api/v1/memories`，传 `supersedes_id`、明确保存同意和同一 `project_id`；建议来源填 `user:correction`。不能改变项目范围，纠正后的原自动条目继续参与自动使用；含秘密标记的纠正不再自动使用。撤销仍用 `POST /api/v1/memories/{memory_id}/retract` 和空对象。

聊天提交无需增加勾选字段。轮次快照新增 `auto_memory_revision`、`auto_memory_references`、`auto_memory_saved_ids`、`auto_memory_expires_at`。引用清单是本轮直接加入的实际记忆，历史衍生内容仍按整段上下文保留；`auto_memory_saved_ids` 只有 Core 落盘后才非空，不能根据回复中的“记住了”推断保存成功。

## 交给 DSH 的前端要求

本次 Codex 只实现后端和接口。由用户直接指挥 DSH 修改 Web `/app`、旧控制台及 Windows 随包 UI/桥，不自动派发。

1. 在现有记忆页放置“自动记忆”开关；读取后端状态，不能在客户端默认打开。开启时说明持续保存与交给当前模型两项范围：仅开启后的明确偏好、个人背景和持续事项，个人跨会话、项目同项目、排除秘密。已在本会话明确同意的用户不需要再次决定范围，但实际写入必须通过认证接口。
2. 保存/关闭后重新读取策略；处理 409 并保留用户原意。全局关闭立即可达，不删库、不隐藏历史、不暗中撤回手动逐轮同意。
3. 复用现有记忆列表、编辑和撤销，展示个人/项目、类别、来源、有效期与未验证状态。显示本轮实际引用和保存的条目；以 `auto_memory_saved_ids` 为依据给出轻量反馈，不能把模型输出当作保存凭据。
4. 聊天发送处在开启时说明“相关自动记忆会用于本轮”，无需逐条或逐轮确认；保留手动选择的独立同意。处理 `MEMORY_UNAVAILABLE` 时自然说明设置或记忆已变化，请用户重新发送，不自动重新外发。
5. Windows 桥允许上述 GET/PATCH；不要在客户端实现第二套抽取、存储或模型调用。验证退出登录、跨 owner、项目切换、刷新重启、关闭后排队请求、纠正、撤销、历史来源显示及无新增记忆时不误报。

## 发布边界

迁移 029 仅新增策略/事件表和可空或安全默认字段，沿用原迁移前一致备份、校验和事务。用户已明确批准本次生产发布、开启和真实模型验证，实际状态与费用见 [P79](ROADMAP.md#p79-auto-memory)，逐次审计摘要见[验证证据](assets/automatic-memory-evidence.json)。持续同意通过上述 owner 接口记录，不因安装新包自动开启其他用户。

本次以现有语音包为基线，保留网页、语音和依赖，只加入性格与记忆的后端文件。版本化迁移加载器要求编号连续，因此同时携带原样的 028 加法表结构；未加入 Skill/MCP 的新运行逻辑或接口。所有切换前备份并核对历史，测试期间保留每次模型调用和失败。自动记忆使用后不可回退到不检查自动上下文失效的旧代码，更不能恢复旧数据库抹去新账本；应使用兼容当前策略/记忆字段的包修复。
