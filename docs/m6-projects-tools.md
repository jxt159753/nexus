# 项目、可控记忆与基础工具

基础工具现在也可通过 [会话工作授权](chat-work.md) 在聊天中使用；写入仍先展示差异并用自然语言逐次确认。下文任务页操作和配置方法继续适用，实际上线记录见 [本轮验证](M6-WORK-VERIFICATION.md)。

当前交付、测试和上线状态见 [路线图](ROADMAP.md#m6项目与可控记忆)，设计取舍见 [ADR 0017](decisions/0017-m6-projects-basic-tools.md)。

## 围绕项目聊天

在“记忆与项目”创建项目，然后在聊天顶部选择它、新建会话。会话的项目固定，切换项目会切换会话列表并清空尚未提交的记忆选择，不混入另一个项目的背景。

项目工作台显示该项目最近会话、任务状态和真实结果。可以进入会话继续讨论或加载更早任务。这里是记录入口，关联项目不会读取电脑文件。

在工作台创建待办、修改文字或取消，并通过“修改历史”查看每次修订。待办属于计划，不会自动运行。选择“已执行完成”时必须选同项目的成功任务作为证据；不是把模型说的“完成”记成执行结果。任务证据只证明对应工具观察，不证明所有更广的项目目标都已实现。

## 明确保存与逐轮使用记忆

1. 在一条聊天输入下点“从本条输入明确保存记忆”，按需要编辑内容、类型和有效期。来源与项目会显示出来。
2. 勾选保存同意并确认，才写入 Core。此步骤不调用模型、不外发记忆。
3. 展开“本轮记忆与明确保存”，查看当前项目有效记忆，可修改并重新确认、或撤销。替代和撤销保留历史。
4. 选最多 8 条，点预览，核对具体内容、来源、类型、验证和期限，再勾选本次外发同意，发送聊天。过期、撤销、被替代或其他项目的条目会被拒绝。
5. 回复旁可以展开本轮引用的实际来源。后续一轮需重新选取和同意；含记忆的旧轮次不会被无声带入近期历史。无记忆的普通近期对话仍按原有 10 轮及字节上限处理。

保存同意与外发同意相互独立。原轮次的结果解读如需再调用一次模型，仍须原结果外发同意并重查记忆有效性；沿用原每轮 $0.05、每日 $1 与共享账本。已发送的数据不能撤回，历史快照不会因撤销而物理删除。

## 文件与命令工具

进入“任务”，选择设备和可选项目，在“工作区基础工具”中选择操作。每次需在下方任务卡审批。新工具默认关闭，必须先由管理员完成以下全部配置：

- Core 对该 Node 登记相应 `tools` 与 `roots=['workspace']`。
- 分别为 owner 和 Node 登记相应 tool + workspace 的持久授权。
- Node 显式设置 `allowed_tools`、本地 `[roots].workspace`；命令还需本地模板与 Core 的精确模板摘要。

文件路径相对于该设备配置的 workspace，使用 `docs/notes.txt` 这样的格式；不是 Core 服务器的目录，不接受绝对路径、`..`、链接或 UNC。

| 操作 | 实际范围 |
| --- | --- |
| 读取文本 | 仅 UTF-8；最多 1 MiB 文件，返回最多 8 KiB 正文及全文摘要；截断会标记 |
| 查找文件名 | 文件名模式，如 `*.py`；页面默认最多 4 层、50 条，扫描最多 2000 条，不读取正文 |
| 预览并写入 | 新完整内容最多 12000 字节；先审批并执行差异预览，核对差异及完整内容后，再提交写入审批 |
| 受控命令 | 只能选择该设备已登记的固定程序/参数模板，固定 workspace 工作目录，8 秒，stdout/stderr 各 8 KiB |

写入预览后，如果路径、内容、设备或项目发生变化，必须重新预览；如果文件被外部修改，Node 拒绝旧摘要的写入。不会自动创建父目录。覆盖使用临时文件替换；不要同时让外部编辑器写同一文件。取消或失败不承诺回滚已发生的效果。

新工具结果只保存在 Core 的任务历史，不自动发送 DeepSeek；本轮聊天和生成 Skill 的工具建议仍使用原有目录。需要模型解读这些新结果时，由用户自行选取明确内容输入聊天。

## 管理员登记命令

命令只由本地可信配置定义，不由网页或模型填写 argv。比如可登记一个已审阅的绝对 Git 可执行文件与固定 `['--no-optional-locks','-c','core.fsmonitor=false','status','--short']` 参数；仍需理解 Git 配置及程序行为。测试命令会运行项目测试代码，不能把其工作目录限制误当成隔离沙箱。

Node TOML 的结构如下；这是结构示例，必须替换程序路径、程序真实 SHA-256，不能直接启用占位摘要：

```toml
[commands.git-status]
executable = 'C:\Program Files\Git\cmd\git.exe'
executable_sha256 = '替换为程序的64位十六进制SHA256'
argv = ['--no-optional-locks', '-c', 'core.fsmonitor=false', 'status', '--short']
```

程序摘要可用 PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath '绝对程序路径'` 查看。模板摘要由 `nexus.node.config.CommandTemplate.digest()` 对规范化配置计算，必须在 Core 对应 Node 的 `command_digests` 中同名登记；摘要不一致不开放命令。更换程序版本或 argv 后重新计算和登记，不继承旧审批。

持久授权使用原管理命令，例如以下命令中的身份需要换成已登记的 owner / Node ID，分别执行；`NEXUS_DATA_DIR` 指向已备份的 Core 数据目录：

```powershell
& ./.venv/Scripts/python.exe -B -m nexus.core.security grant <identity-id> --tool filesystem.read --root-id workspace
```

写入还需 `filesystem.write_preview` 和 `filesystem.write`，命令需 `command.run`。仅改 Node 配置不产生 Core 授权，不能用单次审批绕过缺失的权限。Node 与 Core 都要升级到本版本，旧节点仅使用原能力。

受控命令可以拥有程序本身的文件与网络能力。首版没有任意 shell、模型构造命令、自动安装依赖、删除工具或系统设置工具；运行记录的成功不等于项目目标完成，必须查看退出码及真实输出。
