# Windows 游戏模式

当前实施与验证状态见 [P108](ROADMAP.md#p108-game-mode)。本功能仅控制 NEXUS 在当前电脑上的资源使用，Core 继续管理权限和任务。

## 使用

- 顶部工具菜单（⋯）中的“游戏模式”可立即开启或关闭；设置中可选择“自动检测”“手动开启”“手动关闭”。开启时工具菜单显示状态点。选择跨 App 重启保留，手动选择优先于检测。
- 在已有工具权限的会话中可说“打开游戏模式”“关闭游戏模式”或“恢复自动检测游戏模式”。NEXUS 使用本机 `builtin.game_mode`，普通／完全模式及目标设备授权沿用原插件流程。
- 自动模式读取 Windows 的全屏状态，覆盖全屏游戏和其他全屏应用；退出全屏15秒后退出模式，短暂切换窗口不会频繁开关。窗口化游戏不保证自动识别，可手动开启。

## 开启与恢复

| 功能 | 游戏模式开启时 | 退出后 |
| --- | --- | --- |
| 摄像头手势识别 | 关闭媒体轨道、识别 Worker 和当前手势插件 | 需用户重新开启摄像头 |
| 实时语音和常驻唤醒 | 停止本机采集／播放，不准备新待机会话 | 仅按原开关恢复待机，不重放语音或旧请求 |
| NEXUS 虚拟手机 | 正常关闭专用模拟器，保留磁盘；拒绝启动、截图、输入与动作 | 保持停止，按用户新请求启动 |
| 三维可视化 | 停止逐帧绘制 | 恢复当前视图的绘制 |
| 系统提醒与界面提示 | 暂停通知投递、不弹出提示；提醒原记录保留 | 积压通知静音并只进入通知中心，不集中弹窗 |

文字聊天、历史、普通文件工作和必要设备连接继续可用。其他应用、真实手机、用户游戏、系统设置及不属于 NEXUS 的模拟器不受影响。游戏模式不是取消所有任务；正在执行的原有动作仍保留真实结果与回执。

## 接入

原生 `game_mode_status` / `game_mode_set(mode)` 与 `nexus-game-mode` 事件提供当前状态。Windows 在原 Node 数据目录原子保存 `game-mode.json`（`mode`、`request_id`）；原生检测器写 `game-mode-status.json`（选择标识、`active`、原因、时间和错误）。这些是不含凭据的本机资源偏好及观测，不是 Core 权限。

`builtin.game_mode.status` 返回 `available/applied/active`，`set_mode` 仅接受 `auto/on/off`。模型调用仍走已配置的 `plugin.call@1`、固定版本、Core／Node 策略摘要和原执行日志。请求保存后等待桌面确认；没有新鲜桌面观测不假称已应用。模拟器停机异步进行，其实际停止以原 `builtin.android_emulator.status` 为准，游戏模式返回值不冒充所有后台进程已退出。

自动模式使用 [Windows SHQueryUserNotificationState](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate) 的全屏忙碌／Direct3D状态，不截屏、读取游戏内容或调用模型。旧 Android 独立可视化调用保持默认绘制，不依赖桌面桥或新增资源。

发布需要同时包含新插件目录／Node 与 Windows 原生和随包页面，并按原流程核对 Node 策略摘要；没有新鲜桌面状态的 Node 不登记游戏模式可执行能力，旧桌面查询明确返回不可用。无需数据库迁移或新增外部依赖。覆盖升级前保留现有配置、回执和虚拟手机数据。
