# 上下文与压缩

较长对话可勾选“允许将所选会话历史压成摘要”。接近配置容量时，NEXUS 先修剪大型工具输出，再将较早普通对话压成摘要，保留近期原文、当前输入和本轮选定资料。原始消息与工具证据继续保存；摘要可能遗漏或出错，关键事实应回看原文。

需要主动整理时，点击“压缩上下文 /compact”，核对提示后发送，也可直接输入 `/compact`。每次最多一次摘要调用，沿用当前调用／费用策略；`cost_limits_enabled=false` 时不检查金额上限，但保留调用次数、用量及未知费用记录。没有可压缩历史时不调用模型。停止、中断、摘要无效或未缩小会保留原文，不自动重试。历史太大时可能需要分次明确压缩。

取消“附带本会话对话”只发送当前输入和明确选定资料。取消压缩同意后沿用有界近期历史投影。摘要不会自动保存为长期记忆，也不会自动带入其他项目或其他会话；遇旧记忆/资料外发边界，不把旧同意变成永久授权。

开启工作区工具后，尚未调用工具的普通文字和代码回答仍可用于下一轮。例如先让 NEXUS 给出代码，再说“保存到本地”，可以引用刚才的代码。实际工作步骤、记忆及显式资料引用继续保留各自的外发边界；缺少内容时可在本轮明确提供或重新选定资料。文件是否保存成功以真实写入和读回结果为准，聊天回复结束不代表文件已保存。

已知工具执行或写入预览失败会把有界错误交给本轮模型解释，预览失败不会继续执行原写入。权限撤销、停止、预算耗尽以及执行/费用未知会保留停止状态和工作记录，不为了生成解释自动追加模型请求或重跑。

回复下方展示压缩状态。“查看逐次请求、回复与中断记录”中可核对辅助请求正文、原始来源、摘要、前后估算与费用。token 数是本地估算，实际用量按供应商报告记录。

P88 增加短引用回取：摘要的 `ctx:` 指向获准历史原文，大型工具输出的 `res:` 指向本轮完整结果。已开启工作工具时，模型可用 `context_read` 按字面关键词定位或分页；每页 JSON 最多 2 KiB／700 估算 token，沿用原动作／调用额度。原文与执行状态不因裁剪而删除；引用失效、跨会话或授权改变会拒绝，不自动补授权或重新执行工具。尚未上线，状态见 [P88](ROADMAP.md#p88-context-efficiency)。

连续三次相同只读结果后，第四次相同设备和参数的读取会记录 `WORK_STALLED` 并停止重复执行；变化的结果／参数、中间其他动作和新纠正会打断判定。时间、在线状态、作业轮询及写入／Shell 不参与。整个批次均停滞时沿原预算解释已有结果和限制，不声称目标完成；无法调用模型时提供自然语言兜底。

管理员可在 Core 的 `[models]` 配置：

```toml
chat_context_window_tokens = 1000000
chat_input_tokens = 32768
chat_input_bytes = 32768
chat_compaction_threshold_percent = 80
chat_compaction_retain_percent = 16
chat_compaction_headroom_tokens = 512
```

模型容量、输出预留与本地费用/传输上限共同约束请求。配置只能收紧当前实现的本地限额；不因填写大窗口自动提高预算。具体设计与边界见 [ADR 0022](decisions/0022-dsh-context-compaction.md)，当前版本与验证查 [路线图](ROADMAP.md)。
