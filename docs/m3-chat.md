# M3 自由聊天：使用与运行

支持 DeepSeek 多轮文字、历史、实际增量回复、停止和会话命名/归档，以及已有只读工具的建议、确认、审批、逐次同意后的自动回传或执行后预览及最终回答；本地与生产版本及验收状态以 [ROADMAP](ROADMAP.md#13-m3-补充确认工具时同意自动回传)为准，边界见[架构第 16 节](ARCHITECTURE.md#16-自由聊天与会话任务衔接方案)。

阅读范围：本文保留 M3 单动作建议/确认与最多两次调用的接口。当前默认工作入口已按 [M6 聊天工作](chat-work.md)扩展为配置范围内的文件读写、有限多工具交换、已启用 Tool/Skill 和网页资料；不要求这些新入口重新遵循 M3 的单建议或逐次文件确认。项目与记忆见 [M6 说明](m6-projects-tools.md)，各版本部署状态仍查路线图。

## 配置

沿用 Core 的 DEEPSEEK_API_KEY 环境变量，不向浏览器或 Node 配置密钥。在现有 `[models]` 中显式启用两个开关：

```toml
[models]
enabled = true
chat_enabled = true
chat_max_output_tokens = 2048
```

模型和聊天默认均禁用；不复制第二份 `[models]`。其余预算与价格字段沿用现有配置。默认价格快照在 2026-10-25 UTC 日结束后失效，即北京时间 2026-10-26 08:00；失效阻止新调用，须人工核对更新。样例见 [core.example.toml](../config/core.example.toml)。

Core 启动时迁移 007 新建会话/轮次表，给既有 model_calls 增加 chat_turn_id，不重建旧表或清空历史。沿用版本迁移前的一致备份与校验。运行中的云端升级必须先暂停、停止唯一 Core 并取得备份。现有云端已按用户另行批准完成升级、两轮真实 DeepSeek 和重启检查，结果见 ROADMAP。恢复旧版本须在停机下恢复迁移前的完整备份，不能把 v7 数据库直接交给只认识 v6 的旧代码，也不能丢弃升级后调用账本继续使用预算。

## 手机与桌面使用

1. 登录原控制台，打开“聊天”，选择“新建会话”。聊天不需要 Windows Node 在线。
2. 输入文字，选择是否附带本会话近期已完成对话，点击“发送给 DeepSeek”。按钮旁说明本轮外发内容；不会附加其他会话、记忆、项目文件或工具结果。
3. 继续输入“把第二个方案展开”等追问。最近最多 10 个完整问答轮次参与上下文，同时受 24 KiB 上限约束；裁剪会显示提示。“查看本轮发送内容”可查实际上下文快照。
4. 生成时可点击“停止回复”。停止关闭模型 HTTP 交换，保留已有文本；没有最终用量时保留完整费用预留，不声称费用为零。刷新页面不会自动重发。
5. 首条消息提交时显示输入的短名称，首轮完成后以同一次模型回复中的标题替换，最多 40 字；失败保留短名称，手动改名不会被生成覆盖。可归档及取消归档，归档不删除历史；新会话不自动携带旧内容。
6. 勾选“允许建议系统信息与目录工具”并选择目标设备，再请求“看看这台电脑是什么系统”等操作。模型最多提出一个动作，点击“确认执行”进入原权限流程；目录还需“批准本次任务”。会话中显示真实状态、结果、验证级别和执行记录，也可拒绝建议。
   在新确认卡上可勾选“允许本次白名单结果回传 DeepSeek，成功后自动回答”，再点击“确认执行并回传结果”。这会同意发送该次说明范围内的有限结果和原上下文，成功后无需第二个回传按钮；每轮重新选择，默认未勾选。等待工具或目录审批期间可停止自动回传，工具取消仍用任务卡；本轮最终回答结束后才能继续追问。新流程的本地/线上状态见 ROADMAP 第 13 节。
7. 未勾选自动回传时，工具成功后可在最新轮次点击“预览可发送的结果”，选择所需字段并“更新所选字段预览”，核对实际内容后点击“同意发送这些结果给 DeepSeek 并生成最终回答”。这会再次发送原输入、当时所选上下文及预览结果，最多追加一次调用，费用仍合计不超过本轮 $0.05。结果最多 8 KiB，目录裁剪和字段省略会标明；不发文件内容、凭证或节点身份。预览五分钟失效，新增消息或权限变化需重新核对；已有后续消息的旧轮会保留未回传状态和不能续接的原因。
8. 最终回答生成中仍可停止；失败、停止或服务重启不重跑工具。刷新可看到原建议、工具证据和最终回答；后续追问使用最终回答。迁移前未保存原生工具调用 ID 的历史动作不能续接，请新建一轮；上下文过大时拒绝续接，不静默增加范围。

原“任务”视图仍可使用。聊天文字和代码块不会执行；只有有限的原生函数建议经确认、授权及必要审批后创建任务。模型说“完成了”不代表设备操作成功。聊天入口不支持附件、模型自动派发、自动长期记忆或调用自定义 Tool/Skill；自定义能力的独立页面操作见 [M4 使用说明](m4-usage.md)，实现与上线状态统一见 [路线图](ROADMAP.md#功能状态)。

迁移 008 增加标题标记及动作/任务关联；迁移 009 增加结果外发快照、原生调用及两阶段账本约束；迁移 010 增加逐次提前同意、等待状态和活动轮次约束。旧名称、轮次和账本保留。升级需停机一致备份，不能将新库交给旧代码或丢弃升级后费用账本；实际部署版本统一见 ROADMAP。

## 限额与恢复

- 费用账本与 M2 共用：UTC 每天 USD 1，每轮合计最多 USD 0.05；每天最多 100 次调用。普通聊天一次，工具结果经预览同意后最多追加一次；余额不足或首调用费用未知时阻断，失败不自动重试或续写。
- 单并发模型交换；每会话最多一个活动轮次。单轮模型超时 30 秒，排队总期限 5 分钟；暂停阻止新调用，取消所有同时停止未结束回复。
- 输入最多 2000 字符/6000 UTF-8 字节；回复最多 2048 token/32 KiB。达到输出上限标为未完整结束，用户可明确发送新一轮继续。
- 全局最多 100 个会话、10000 轮，每会话 200 轮；每分钟最多 10 个新聊天请求，达到全局内容存储上限会拒绝新增。满额不自动删除历史。
- Core 重启不重发生成中的轮次，保留部分文本并标为中断、费用未知。已完成历史仍可查；查询、恢复、标题、归档不调用模型。
- 价格过期、预算不足、暂停或数据库不能可靠写入时，不启动新模型调用。

## HTTP 接口

沿用 owner 会话、Origin 和 CSRF 守卫；写操作需要有效 X-CSRF-Token。

| 路径 | 用途 |
| --- | --- |
| `POST /api/v1/chat/conversations` | 按 request_id 幂等创建会话 |
| `GET /api/v1/chat/conversations` | 每页最多 20 个；before 游标、archived 过滤 |
| `PATCH /api/v1/chat/conversations/{id}` | 更新 title 或 archived |
| `GET /api/v1/chat/conversations/{id}/turns` | 会话当前 revision、活动轮次 ID 及最多 20 轮历史；before 可向前翻页 |
| `POST /api/v1/chat/conversations/{id}/turns` | 提交当前文本与外发同意；expected_revision 固定会话上下文 |
| `GET /api/v1/chat/turns/{id}` | 状态、真实增量文本、费用状态及实际发送的上下文 |
| `POST /api/v1/chat/turns/{id}/stop` | 幂等请求停止，返回停止中或实际终态 |
| `POST /api/v1/chat/turns/{id}/action` | 确认/拒绝具体摘要绑定的建议，重复确认返回同一任务 |
| `POST /api/v1/chat/turns/{id}/result-preview` | 可选 fields 数组（默认全部白名单字段），返回实际结果、摘要、expected_revision 和五分钟期限；不调用模型 |
| `POST /api/v1/chat/turns/{id}/result-consent` | result_digest、expected_revision、allow_model=true 续接本轮；重复确认不增加调用 |

发送示意，UUID 和 revision 使用前一步实际返回值：

```json
{
  "request_id": "84d8c019-94a7-45ea-919c-48a88c4b9950",
  "expected_revision": 1,
  "text": "我想做一个小游戏，先给我两个方向",
  "include_context": true,
  "allow_model": true
}
```

客户端不提交 system/assistant 历史或自定角色。重试沿用完全相同的 request_id 和正文；内容或上下文 revision 改变时返回冲突，须核对后新建请求。`GET /api/v1/models/usage` 新增 chat_enabled，旧 enabled 字段仍表示模型总开关。

工具建议需在提交中设 allow_tools=true 和选定的 node_id；两字段默认 false/null，节点身份不发给模型。动作决定正文包含 decision（confirm/reject）及实际返回的 64 位 proposal_digest，不能在确认时修改节点或参数。暂停、取消所有、过期、归档或权限/资源变化阻止尚未提交的确认。

动作决定可另设 allow_result_model=true，表示批准该次白名单结果和原上下文在工具成功后自动发送。重复确认不得改变这一选择；目录仍需原任务审批。迁移 010 增加逐次同意和等待状态，旧记录默认不回传；等待期间 stop 只停止后续自动外发，不冒充工具已取消。接口新增 auto_result_status/auto_result_allowed，UI 按实际任务状态显示“工具已完成，结果尚未发送给模型”。

M5 在上述链路上增加逐次允许的固定流程建议、参数表单与多步进度；使用和新增接口见 [聊天中的多步流程](m5-chat-skills.md)。原两工具与提前结果同意继续保留；流程的结果解读采用执行后预览同意。具体版本和上线状态仍以 [路线图](ROADMAP.md#m5从聊天完成多步任务)为准。
