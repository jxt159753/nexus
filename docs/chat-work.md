# 在聊天中完成有限工作

选择目标设备，在新建或已有会话直接提出目标。已配置 workspace 内读取、查找和写入默认可用，不需要会话授权或回复“同意写入”。Core 继续检查持久身份权限、工作区及工具交集；新能力版本仍须先批准。

工作工具默认开启，可以关闭。发送提示说明本轮输入、所选上下文、能力目录和实际结果发送给 DeepSeek，包括文件正文和命令输出。记忆保存与引用同意仍独立。

可直接提出“看看节点是否在线”“查找所有 txt 文件”“读取 notes.txt”“使用已启用的流程做工作区概览”。模型从当前有效目录中选择；开启对应创建能力后，也可在会话中根据明确请求或当前任务缺口创建插件或 Skill 候选。创建与启用分开，规则见下文。

例如：“列出工作区文件，并把电脑信息写入一个新的 txt。”独立工具可在同一批提出，Core 按序执行；依赖前一步结果的动作需等待实际结果。写入在内部完成真实差异预览、摘要绑定、文件变更检查及读回验证。外部修改导致旧摘要失效，刷新不重复执行。

`write_file` 同时支持新建和覆盖 UTF-8 文本文件；新建不需要单独的 create 工具，`content` 为空字符串时创建空文件。路径相对于 workspace，父目录须已存在，每次正文最多 12000 个 UTF-8 字节。只有当前设备与身份均获准使用写入及预览工具时，聊天目录才提供 `write_file`；未提供工具时应说明当前不可用，不能据此断言 NEXUS 不支持新建文件。

12000 字节不是 12000 字符，中文通常每字占 3 字节。完整工具批次中某个已提供函数的参数不合格时，整批不执行，Core 在交换日志保留失败原因，并在原 4 动作/5 次模型交换内返回未执行证据供模型修正。超大文件可精简或在剩余动作内拆文件；未知结果、截断、权限拒绝和重启不会因此自动重试。具体见 [ADR 0033](decisions/0033-tool-argument-feedback.md)。

模型输出配置上限默认 256000 token，实际调用按本轮剩余预算收紧，默认首次最多 33474；具体见[聊天配置](m3-chat.md#配置)。输出限额与单个文件的 12000 字节限制分别检查，较大网页可拆成 HTML/CSS/JS 等文件，但仍受剩余动作和完整请求大小约束。`finish_reason=length` 的整批工具调用不执行，记录未完整结束，不能把模型的“准备写入”当成文件已创建。

用户于 2026-10-23 批准将生产 `models.cost_limits_enabled` 关闭，金额不再收紧上述输出或阻止网页/工具工作；既有安装默认仍开启限额。实际部署见 ROADMAP，策略见 [ADR 0032](decisions/0032-owner-cost-limits.md)。已知/未知费用、调用次数、超时、动作数量和执行恢复仍照常处理。

Core 启用 `models.web_enabled=true` 后，可自行调用 `web_search` 与 `web_fetch`，复用 Core 已有 DeepSeek 密钥。搜索词最多 128 字符、每次最多 5 项标题/链接/摘要；抓取仅公开 HTTP(S) URL，不接受用户名/密码、内网、登录 Cookie 或本机文件。Core 只访问固定 DeepSeek API，不直接连接目标网站；站点及抓取安全策略由供应商执行。

每个网页请求限 10 秒、256 KiB 响应，页面正文返回最多 8 KiB，截断会标记。网页是外部资料，不能授予权限或指挥工具；回答应引用来源链接，工作卡也保留链接。搜索只发送该查询，不附带整个用户原问题。具体 URL 与查询会发送给 DeepSeek。

按[官方计费](https://api-docs.deepseek.com/guides/search/)，成功且有结果的请求每次 USD 0.00075，空搜索结果和非成功响应不计请求费；配置费用上界与价格有效期在发送前核对。网页和模型共用原金额及调用次数账本，总调用数包括网页请求，聊天分别显示模型和网页数量。超时或中断保留该次预留，不自动重试。

网页超时、断流或返回无效内容后，已结束请求的失败结果会交回模型，可利用已有资料或改用其他来源；费用未知仍按完整预留计入额度，同一轮不重复相同的待核对请求。取消与重启遗留不自动继续。工具和执行错误最终使用自然语言解释；整轮必须停止时，在原有授权与 5 次交换内至多生成一次只解释、不调用工具的回答。模型不可用、用户停止、撤权或额度不足时，仍显示自然语言兜底和已取得的来源，不只留下错误码。解释完成不代表工具成功，见 [ADR 0036](decisions/0036-natural-failure-feedback.md)。

固定命令仅允许管理员配置的程序、固定参数和摘要；默认工作可执行这些模板，任意命令字符串、参数或 shell 不可用。旧显式授权仍可选择逐次用聊天确认命令；新 Tool/Skill 具体版本批准不变。

每轮最多 4 个动作、5 次模型交换，共用 USD 0.05；每日额度仍为 USD 1、100 次 API。默认工作范围由已有配置产生，内部最长 5 分钟、20 次底层操作，不是新的用户确认。派发前重查版本、范围和权限；未知结果、失效或超限停止。

已启用的 Tool/Skill 先以简介展示给模型；不熟悉输入契约时可调用 `inspect_capability` 查看该固定版本详情，再决定是否执行。查看详情本身不运行工具、不启用版本，但占用一个工作动作，后续模型交换也计入上述上限。复杂契约按需加载可减少重复上下文，简单能力则可能多用一次交换。

上下文按完整请求的 token 估算、模型窗口/输出预留和字节上限管理。勾选本轮压缩同意后，Core 先修剪大型工具数据，再将带来源的旧普通历史压成摘要，保留近期原文、当前输入、选定资料及调用配对；支持 `/compact`，每轮最多一次额外摘要，共用原费用上限。未同意压缩时沿用有界历史裁剪。完整工具证据和原始对话保留，摘录不可作全量统计；失败或压后仍超限时停止，不自动保存记忆或重试。自 2026-10-21 起，已完成工具轮次自动进入后续普通上下文；显式记忆/引用仍需重新同意。详见[上下文与压缩](context-compaction.md)。

“停止本轮工作”关闭模型/网页交换并请求取消真实关联执行；暂停使用原全局控制。Core 重启不重发旧付费请求。原显式授权接口仍可撤销，旧待确认写入不会因升级自动执行；这些旧操作可以用“同意”“不同意”答复。

节点状态展示 Core 观察到的在线/离线、忙闲、心跳年龄、工具与资源别名及观测时间。离线时忙闲不可确定；此工具不提供 CPU、内存、传感器或系统负载采样。

接口：

- `GET /api/v1/chat/work-catalog?node_id=...`：权限过滤后的固定目录及摘要。
- `POST /api/v1/chat/conversations/{id}/work-grant`：明确同意的有界会话授权。
- `DELETE /api/v1/chat/conversations/{id}/work-grant`：撤销并停止相关工作。
- 默认聊天提交 `workspace_work=true`、`work_digest`、`allow_work_results=true`，使用已有配置及本轮外发同意；不能同时指定 `work_grant_id`。
- `POST /api/v1/chat/turns/{id}/permission`：绑定步骤、轮次 revision、幂等请求号及自然语言答复。

默认权限与网页设计见 [ADR 0019](decisions/0019-workspace-defaults-web-tools.md)，上下文与能力详情见 [ADR 0020](decisions/0020-dsh-context-harness.md)，原显式会话基线见 [ADR 0018](decisions/0018-scoped-chat-work.md)。实际状态与部署证据统一见 [路线图](ROADMAP.md)。

## 在会话中创建插件或 Skill

可说“创建一个统计文本长度的插件”“创建一个工作区概览 Skill”，也可提出当前任务，让 NEXUS 判断是否确实缺少可复用能力。模型先检查现有目录，适合组合既有工具时创建 Skill，需要新增 Python 处理逻辑时创建插件；一次性任务已有工具能完成时直接使用。是否需要创建由同一聊天模型判断，没有新增分类器或后台生成循环；真实模型的选择质量仍需实际场景验证。

| 对象 | 会话工具与配置 | 创建后的状态 |
| --- | --- | --- |
| 插件 | `plugin_install({release})`；Core `plugins.enabled=true` | 保存不可变包并在合格 runsc 环境自动测试。normal 等待 owner 批准具体版本；full 只在测试通过且预授权仍有效时自动启用 |
| Skill | `skill_create({reason,skill})`；Core `extensions.enabled=true` 且 `generation_enabled=true` | 保存 manifest、Markdown、1–3 个固定步骤和测试，自动完成契约替身测试；normal/full 均保留具体版本批准及启用步骤 |

上述创建要求本轮允许工具及结果外发、有效 standard 工作范围；默认 `workspace_work` 路径可用，无需额外开启第二份授权。模型不能打开配置开关、修改权限模式或突破 read/计划模式。新创建候选和隔离/替身测试不再单独询问执行确认；升级前已在等待确认的插件步骤仍需原答复。审批与实际宿主执行仍受原规则约束。

`skill` 使用现有 `SkillGeneration` 契约，必须含至少一项覆盖全部有序步骤的测试。支持原有 system.info/filesystem.list、固定生成 Tool，以及 `skill_native_steps_v1` 的固定 builtin.shell/MCP 步骤；先通过 `plugin_inspect` 取得原生工具契约和摘要。Markdown 只是说明，不执行。创建不覆盖同名不同内容，不自动生成修订；相同内容、相同节点的重复请求复用候选和测试记录。

步骤结果包含实际 `version_id`、摘要、`test_status`、批准和启用状态。Skill 还返回 `created`、`execution=not_run`、`review_url`；`approval_required` 表示尚未获批，`approval_available` 表示测试通过、可审阅批准，失败版本仍需要批准且当前不能批准。`verification=skill_contract_standins_only` 只代表契约替身验证，不能称真实 Shell/MCP 已运行。失败候选保留且不启用；沙箱离线时插件报告测试不可用。具体版本可在原能力/插件管理入口审阅，沿用原认证接口批准、启用和停用。步骤工具/profile 以当前服务器实际提供的契约为准，源码中存在原生步骤不代表已部署。

创建仍占用每轮 4 动作/5 交换及原操作额度，检查、生成参数和反馈都在原聊天账本内，不调用第二个生成模型。Core 重启后保留候选并等待原恢复确认，不重发模型请求；取消后保留已创建证据但不开始新的测试或执行。此功能不包括持续修订、自动回滚或 Core/Node 源码自改。设计见 [ADR 0037](decisions/0037-chat-capability-creation.md)，实际交付与部署见 [P77](ROADMAP.md#p77-chat-creation)。

前端无需新增发送协议。交给用户控制的 DSH 的适配要求：复用 `work_steps` 展示上述字段，区分“候选已创建”“测试通过”“待批准”“已启用”；原版本审阅入口按 `version_id` 打开，不因模型文字或步骤 succeeded 隐藏待批准状态。未配置时按 work-catalog 显示实际能力。本批不修改或派发前端。
