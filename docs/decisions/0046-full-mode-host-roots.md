# ADR 0046：full 模式的宿主目录访问

状态：接受（2026-10-25，用户明确要求实现、验证、部署及更新 Windows）。

full 模式允许所选设备在 Node 当前系统账户权限内访问工作区以外的本地目录。normal 保持原有工作区文件工具与宿主命令授权规则。工作目录不构成 Shell、终端或 MCP 的文件隔离；本次不新增管理员权限，也不改变 Android 的系统沙箱。

在现有文件参数及 `plugin_execute` 外层增加可选 `access_root`，表示目标设备上的绝对目录。`path` 继续相对此目录；省略时使用已配置的 workspace。例如读取桌面文件使用 `access_root="C:/Users/name/Desktop"`、`path="note.txt"`。此字段覆盖列目录、读取、行分页、文件名/内容搜索、写入/编辑预览、图片及固定命令的工作目录；插件将它传给文件、交付物、LSP 与进程的默认目录，组合调用继承本次范围。Shell/终端原有 `workdir`、工作目录工具的 `cd` 和 MCP 参数继续按已有宿主能力执行。

Core 在插件步骤准备时及每次任务授权/派发前，核对绑定的有效 full 工作授权、owner、设备和模式指纹。normal 或无对应工作授权不能使用 `access_root`，具体动作批准也不能替代 full。切换模式、撤权、停止和授权过期后，尚未派发的旧任务不能继续；不撤销已经发生的外部效果。Node 仍只接受认证 Core 的具体命令，并保留本地工具配置、回执、真实进程停止与结果检查。

文件实现复用原有路径组件检查、普通文件/链接保护、有限读取、CAS、原子替换与读回。预览摘要包含非空 `access_root`，防止跨目录复用预览；旧命令缺省不序列化新字段，原命令摘要、审批和回执保持。目录字段不授予执行器或访问不存在设备的权限。

没有新增依赖、数据库迁移或前端界面。以线上固定包合入本项，先更新兼容旧命令的 Core，再更新 Windows Node。旧 Node 无法解析带新字段的命令时拒绝执行；升级前不得声称区外文件能力可用。验证与发布证据统一见 [P91](../ROADMAP.md#p91-full-host)。
