# ADR 0027：会话文件与图片上传

日期：2026-10-21。用户明确要求加入图片和文件上传，随后选择“先支持所有文件上传，内容解析分批补齐”。前端仍按用户既定要求由 DSH 实施。批准和实际交付只维护在 [ROADMAP](../ROADMAP.md)。

## 选择与边界

附件归唯一 Core 保存，不写入 Node 工作区，不新增 Node 文件权限或第二个存储服务。原文件作为 SQLite BLOB 与 owner、conversation、上传幂等键及 SHA-256 同事务保存，复用现有一致备份。文件名只是显示数据，不能成为磁盘路径；任意扩展名均可保存和下载，不执行、解压、导入或安装文件。下载原件固定为 `application/octet-stream`、`Content-Disposition: attachment`，继续使用认证、CSRF、无缓存和 nosniff。

迁移 022 新增附件及轮次关联表，仅给旧 chat_turns 增加默认空的附件清单，不改写旧任务、授权、费用或消息。原件和有限预览同事务提交，失败不产生半个附件。相同 owner/request_id 的重复上传必须绑定同一会话、名称、声明类型、长度和摘要；重传不重复占用容量。上传不触发模型，也不增加会话 revision。附加到轮次和轮次入库同事务，之后不能通过删除附件破坏历史证据。

| 资源 | 固定边界 |
| --- | --- |
| 单个原文件 | 16 MiB，任意扩展名，支持空文件 |
| 附件总量 | 256 MiB（含预览）、1000 条（含删除墓碑），满后拒绝，不自动删旧附件 |
| 单 owner 上传速率 | 每分钟最多 20 个新附件，幂等重传不新增计数 |
| 传输并发 | 上传/原件下载共用 2 个槽；下载分块输出，最多 30 秒，结束/断开/超时释放槽和大块内存 |
| 上传接收 | 30 秒、按实际收到的字节限制，拒绝压缩传输；不只信任 Content-Length |
| 当前轮次选择 | 最多 4 个附件，逐轮预览、摘要绑定和明确外发同意 |
| 文本预览 | 最多 1 MiB 的严格 UTF-8 文本，发送最多 8 KiB 并明确截断；不解析容器和 Office/PDF |
| 图片快照 | 沿用 P54 的 4 MiB/8192px/1600 万像素源上限，实际图片最多 1024px/8 KiB，可能有损、缩小、首帧和透明白底 |

## 上传与内容理解分别记录

有界 UTF-8 文本可作为不受信资料发送；PNG/JPEG/GIF/WebP 按字节识别，复用原图片归一化代码。PDF、Word、压缩包、可执行文件、音视频及其他尚未支持的内容均可上传、保留和下载，只向模型提供元数据及明确的“未解析/未读取”说明。损坏图、大图、缺少图像解码器也保留原件并显示预览不可用，不伪造成功分析。文件名与浏览器声明的 MIME 不决定图片类型，不执行 HTML/SVG。

图片归一化抽为共享的纯字节模块；Node 保留原路径保护并调用同一实现，Core 不导入 Node 模块。Core 将图片解码交给独立的固定 Python helper，单并发、10 秒、32 KiB 输出边界，环境不继承模型或 Node 凭证，取消/超限结束真实 helper；POSIX helper 另设自身 CPU/地址空间上限。这里是可信媒体处理进程，不宣称是不受信代码沙箱。Pillow 13.0.0 继续是可选固定 extra，只有承载看图功能的主机需要安装，Core 主进程不导入 Pillow。

## 模型与历史

上传不等于发给模型。模型预览给出本轮选择、可读取内容、实际图片、截断与未解析状态，并计算摘要；提交带 `attachment_ids`、`attachments_digest`、`allow_attachment_model=true`，Core 在提交和每次模型调用前重查归属、清单和摘要。图片仍须显式启用 `chat_images_enabled`，未启用时预览明确该图片只发送元数据。

附件正文和图片仅作为 user 数据，不能自报 system、权限或执行成功。原 32 KiB 完整请求、输入 token、输出、每日/单轮费用、次数及取消规则保持；超限不预留费用，不截断 base64 或另起调用。当前附件与近期历史可共同使用；包含附件的旧轮次像显式记忆/资料引用一样形成隐私边界，不自动在后续普通历史或压缩中沿用。需要再次阅读时重新选择附件并同意；原显式历史引用可在重新预览及同意后引用最终文字，仍复查来源可用性。

## 接口与客户端

支持原始字节上传以及有界 Base64 JSON 上传，下载同时提供原件字节和 Base64 JSON，后者用于现有 Windows 字符串 HTTP 桥适配。两者使用同一存储和授权。图片预览只提供经过验证的 PNG/JPEG，不直接内联原文件。接口契约见 [附件使用说明](../chat-attachments.md)，给 DSH 的实现要求见 [前端工作单](../CHAT-ATTACHMENTS-FRONTEND.md)。

本轮不修改前端、Windows 原生桥或安装包，不把后端可用视为实际界面已完成。客户端限制、部署和真实模型效果分别验证。
