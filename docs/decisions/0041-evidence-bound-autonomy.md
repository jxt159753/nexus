# ADR 0041：以任务证据约束目标续跑与运行治理

日期：2026-10-23。

用户要求补齐目标验收、依赖规划、持续上下文、插件独立测试/回退、事件感知和长期运行。复用现有 Core、Harness、SQLite、Node 回执及 runsc 测试链路，不增加第二个规划中心、消息服务或模型心跳。实施和验证状态见 [P81](../ROADMAP.md#p81-autonomy)。

决定：

- 目标计划是已有任务的投影。依赖、条件、检查点和证据持久化；完成由确定性断言核对当前有效任务结果。验收条件一经定义不允许模型放宽；机器验证标签不代替用户验收。
- 跨段继续使用最初的根账本、期限和授权。恢复默认关闭，owner 单独开启；结果未知时先对账，原请求已提交则补记，不再派发。无进展与重规划均有界。
- 上下文检索复用原同意边界，个人长期记忆不承载目标状态。事件来源必须显式订阅；轮询零模型，事件仅唤醒原来等待该来源的目标。
- 独立业务用例由 owner 管理，与候选自带样例分开。比较固定基线，按真实结果观察；回退先隔离失败候选，等待停止证据，重查旧版本批准和权限。宿主安全不由测试样例担保。
- 冷归档使用同库事务和有界压缩，保留身份、哈希、费用和执行关系。逻辑快照不可变，物理字节仅能在存在已读回冷副本时搬迁；损坏时失败关闭。Node 冷回执保留幂等身份。
- 后台健康服务监督现有工作协程与容量；故障停止新执行，告警按状态变化记录。保护账本和未知记录，不靠删历史或重置预算维持运行。

取舍：计划与断言覆盖范围仍取决于声明内容，不能解决任意任务的语义正确性。事件采用有界轮询而非新建常驻平台监听器，延迟至少受订阅间隔影响。归档保留全部证据，磁盘需求仍随长期使用增长。独立用例与自动回退不等于 Core/Node 源码自改、任意 Skill 自动批准或生产自动发布；M9 其他能力按其独立批准范围处理。前端由用户控制 DSH，接口与工作单见 [自主任务接口](../autonomy.md)。
