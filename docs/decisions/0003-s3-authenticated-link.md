# ADR 0003：S3 认证连接与任务状态分离

日期：2026-10-17。状态：按用户“完成S3并上传github”实施；技术与用户验收状态见 [ROADMAP](../ROADMAP.md)。

## 决定

- 复用 S2 的 SecurityHTTP 握手及逐消息认证接口，使用 P02 的 25 种 v1 契约；新增 Core 单 worker 启动入口、Node 主动连接入口及严格 TOML 配置。
- Core 的可信 Node 工具/资源配置与持久 owner / Node 授权共同限制自报能力；会话替换先改变当前连接权威，旧消息无法继续使用旧 session。
- 连接和在线状态为可重建内存观测；接入/断开审计使用现有 Core 事务。心跳、重连、凭证撤销和 Core 重启均不能直接改变任务终态，不为连接层新增业务状态机或数据库模式。
- 采用 websockets 17.1 作为唯一新增安装包，同时支持 Node 客户端和 Uvicorn Sans-I/O 服务端；其他依赖版本保持不变。WSS 保留证书/主机名校验，WS 仅允许显式字面 loopback 开发模式；不跟随重定向或环境代理。
- 复用一个可移植数据目录进程锁辅助模块供 Core 与 Node 使用；Core 不导入 Node，平台工具生命周期仍封装在 Node 内。
- 两端实施固定消息、速率、连接、队列、发送等待及重连退避限制。Core 只接收传输证据，不提前结算或 ACK；执行派发当前明确拒绝，P07 必须实现持久授权/attempt 事务后才能启用。

## 后果

S3 可以独立验证 Node 实体、本机认证通信、能力交集、心跳和重连，保留 P07 的权威闭环边界。查询缓存回执和处理可信 ACK 不等于实现完整恢复；网络对账和全局控制仍属 P08。实际远程 TLS、Android、Windows 10 与 Python 3.12 未经本轮验证。
