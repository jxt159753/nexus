# ADR 0007：S7 传输与恢复验收边界

日期：2026-10-18。用户授权“完成S7”，后确认 Android/可信远程 TLS 尚未准备，先完成本机检查。阶段状态由 [ROADMAP](../ROADMAP.md) 管理。

沿用单活 Core、独立 Windows Node、直接 TLS、显式授权和零模型，不新增运行依赖、代理服务、通用运维框架或第三种工具。

- 真实 HTTPS/WSS 测试使用 OpenSSL 临时生成 CA/服务器证书，只向测试 SSLContext 和 Node ca_file 提供信任；不安装系统 CA。真实握手验证信任链和主机名拒绝，认证/Origin/审批继续经过现有应用路径。OpenSSL 是测试工具，不是运行依赖；缺少它时明确跳过相关检查。
- 一致恢复采用停止两个进程后分别使用 SQLite backup，再复制到全新数据目录。保留源库及备份、检查 quick_check/外键/摘要，启动前确保旧实例停止。先验证 Node 离线，再重新认证；不复制在线状态，不重置审批绑定和未知结果。
- 文档明确当前入口使用 Uvicorn 直接 TLS 且禁用代理头。部署层 TLS 终止仍是未来可设计选项，不把远程明文入口或伪造转发头作为替代。
- 自动化传输、独立进程和恢复证据只证明本机对应层级的行为。Android 真机、远程可信证书及实际手机网络恢复必须单独记录；条件不足时保留未验收项，不宣布 M1 完成。

代价是设备验收仍依赖用户准备真实网络和受信证书。这样无需扩大信任或配置权限；未来恢复更旧快照时，仍须人工核对备份后的撤销/轮换及未决执行。操作见 [S7 部署](../s7-deployment.md)，实际证据见 [S7 验证](../S7-VERIFICATION.md)。
