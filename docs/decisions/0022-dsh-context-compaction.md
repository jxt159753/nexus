本次只调整容量及必要调用方，不复制 DSH 的其他执行机制；摘要仍最多 1024 输出 token、需逐轮同意、最多一次辅助调用。原文、调用配对、权限、停止、未知执行先对账保持。无前端、Node、依赖或数据库迁移。以下正文为 2026-10-21 的历史决定，旧 32 KiB/32768/512 容量由本节替代；实际交付见 [P99](../ROADMAP.md#p99-context-capacity)。

## 请求与压缩

- 唯一计量函数估算完整 system/messages/schema 的 token，同时测量真实 JSON 字节。ASCII 约 4 字符/token、其他文字约 1.5 字符/token，加固定开销；这是启发式估算，不是精确 tokenizer。供应商报告用量仍是费用核算依据。
- 按可信配置中的模型窗口、输出预留、headroom、本地输入 token 和字节上限共同准入。默认 80% 压力触发；原始 HTTP 传输上限和费用预留保持。
- 每轮独立选择 `allow_compaction`；旧客户端默认 false，保留原近期问答/确定性摘录行为。网页明确提示最多额外一次摘要调用及共用费用上限。未选上下文不会自动拉取历史。
- 同意后可使用本会话最多 200 轮已有普通对话及已完成压缩摘要；遇记忆、显式引用或含实际工作步骤的轮次即停止，不借摘要复用旧的私有资料同意。仅开启工作区工具、未提出任何工作步骤的纯文字/代码回答仍是普通历史。明确选定的记忆/历史资料和当前任务输入保持原文。
- 工作请求先对大型工具数据作显式首尾投影，保留所有调用 ID、参数、结果配对、状态及验证信息。完整工具证据仍在原任务/步骤。只有带来源的旧普通历史可以进入模型摘要；当前原生工具链不被摘要拆开。
- 压缩选择能够装入单个辅助请求的最早完整历史前缀，按 token 保留近期完整轮次。与 DSH 相同保留基础 system 和历史前缀，末尾追加摘要指令；工具禁用，输出最多 1024 token。摘要按目标、决定/约束、事实/证据、已完成、待完成和下一步组织。
- 每轮最多一次压缩、不自动重试；工作原有 4 动作/5 工作模型交换保留，辅助调用单独计数且费用合并到同轮 USD 0.05、日 USD 1/100 次。未知费用继续占用额度。压缩失败、摘要无效/不缩小、单个消息过大或压后仍超限时明确停止，保留原文；很长的历史可再次明确发起 `/compact`。
- `/compact` 是仅压缩当前会话历史的普通持久请求，需要上下文/压缩/模型同意，不携带工具或私有引用；空历史确定性返回且不调用模型。网页按钮填入命令，用户核对后发送；不会悄悄付费执行。

## 记录、停止与恢复

迁移 020 增加模型可见 surface、消息来源映射和 `chat_compactions`。原 `context_json`、原始消息、任务证据和费用账本保留；源消息、来源轮次、摘要指纹、选定范围、估算前后大小、结果及中断单独记录，来源字段由数据库触发器保护。每次辅助 HTTP 正文同样在费用预留事务内保存，提交后才调用。

只有已完整返回、结构合格、token 估算和字节均缩小、surface 未改变的摘要才替换选定前缀。后续轮次复用前重查同会话原始来源及内容摘要，不能跨隐私边界复用。生成摘要始终标为可能遗漏/出错的参考资料，不能授予权限或改写真实任务状态。

停止取消真实模型交换；已付费用与部分输出留日志，原文不替换。重启将未完成压缩与交换标中断/未知，不自动重发；已完成检查点持久复用。纠正只在正常工作模型调用时标记生效，不被辅助摘要调用提前消费。

部署使用固定 wheel、Linux 候选验证、暂停/空闲检查、停机一致备份、018–020 前向迁移与旧字段逐表比对，再切换唯一 Core。Windows Node 和 WSL Sandbox 的运行版本及原身份/目录/权限/密钥保持；新增文件/界面工具只有相应执行端升级配置后才可使用。

## 跨轮纯文字与代码衔接修复

用户反馈“生成猜拳代码后，保存到本地却要求重贴内容”，并要求参考 DSH GitHub 修复。固定核对同一提交的 [Agent 消息落盘](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/agent-loop/src/agent.ts)、[实际工具配对边界](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/compaction/compaction/src/tool-pairing.ts)和[按可用工具提供写入指导](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/fs/tool-fs/src/write.ts)。借鉴其按实际消息和工具事件构造上下文的机制，不把工具目录或授权范围本身当作工具执行证据。

普通历史、压缩历史和压缩来源重查共用同一判定：记忆、显式资料引用及已有工作步骤保留原边界；只有内部工作范围、没有工作步骤的完整回答可继续带入和压缩。原工具调用/结果、审批、费用和恢复流程不变，不自动追加原始工具数据或沿用旧私有资料同意。

工具提示随实际目录提供：有 `write_file` 时，实施程序/创建文件请求应生成工作区产物，省略文件名可选合理相对文件名，覆盖前检查原文件；明确只要示例/解释时保持文字回答。追问保存代码应使用上轮原文；保存源代码不意味着获准执行。另说明聊天历史、显式记忆编辑器和文件保存的区别，不能虚称已保存或否认已有记忆功能。无需迁移或新增依赖；本轮证据和未验证项见 [修复验证](../CHAT-CONTINUITY-VERIFICATION.md)。

用户追加失败反馈与发布要求后，将已知写入预览失败接入原 `result` 路径，与普通执行复用有界任务反馈，保留公开错误码/信息并明确 `phase=preview`、未执行写入；补齐生成 Tool 控制器错误。仅在确认尚无任何子执行且权限仍有效时，准备阶段错误才可返回模型；原生调用配对、动作和预算上限不变。权限拒绝/撤销、取消、未知效果与未知费用继续停止，不因报错自动重试旧执行或扩大权限。
