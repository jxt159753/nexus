# ADR 0028：NEXUS 原生插件、权限模式与自写插件

日期：2026-10-22。用户明确批准原生插件系统、移植 DSH 工具、部署及 GitHub 交付；子代理、Agent Team、Ralph、插件市场暂缓。DSH 参考固定为 `687f282e8625c6b8d11ff58211a90524be2e4317`。本文件是设计决定，完成证据只记入 [ROADMAP](../ROADMAP.md)。

## 已确定的边界

- Core 仍是唯一权限、任务、费用与恢复权威，不引入 DSH/Cordis 代理运行时。插件描述、模型输出和插件结果不能自行修改权限。
- 全局 `normal/full` 是未覆盖会话的默认值；会话可覆盖或清除覆盖。默认 normal。改变模式仅由已认证 owner 的 HTTP 请求执行，模型工具不提供此操作。改变后阻止沿用旧授权的新执行；已派发操作记录真实结果，降权不是回滚。
- normal 在已授权任务范围和有效期内连续执行，需要额外权限/高影响操作时请求确认；full 在当前任务、设备与期限内免交互确认。认证、静态能力交集、预算、输出/运行限额、取消、摘要及真实结果核验不被绕过。
- 用户选择 Windows 宿主执行：Shell 和已启用宿主插件以 Node 当前用户权限运行。工作目录不提供文件安全隔离；工作进程与 Windows Job 只负责故障/资源/生命周期管理。剥离执行进程的 NEXUS 令牌等环境凭证，不宣称能阻止该用户访问本机其他数据。
- 新插件按同一 manifest、输入/输出 schema、不可变版本/摘要和执行协议注册；采用目录摘要与按需发现，避免把全部插件 schema 塞入每轮 32 KiB 请求。Core 不导入用户生成的插件代码。
- 自写插件从候选、契约检查、受控测试进入安装/启用。normal 批准具体版本；full 的自动启用以当前有效模式为预授权并落盘，测试完成后再次核对。失败不自动启用，不无限生成/修订；费用仍共享原账本。
- 原固定 `run_command` 的新调用被宿主 Shell 替代；保留历史契约/结果解析和未决执行对账，不将旧 Skill 自动升级为宿主代码权限。
- 安装来源支持本地包与固定 GitHub 版本，保留来源/许可证、版本、依赖和摘要；本次不建立插件市场。第三方代码安装与执行的信任由 owner 的权限模式和批准记录表达。
- 前端及 Windows 原生桥由用户直接控制 DSH 实施，Codex 提供后端与[接入工作单](../PLUGINS-FRONTEND.md)，不自动派发。

## 顺序与验证

先实现权限与注册生命周期，再接执行、查询/交互/调度和生成；每个工具必须有真实执行器，未配置的能力明确不可用。复用原 task/attempt/回执/账本，所有跨重启动作先核对，未知结果不重跑。部署升级前备份并保留历史，只有真实证据支持的能力才能记录为完成。
