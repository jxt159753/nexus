# ADR 0032：按 owner 明确指令关闭金额限额

日期：2026-10-23。状态：已采纳。用户明确要求“先移除费用限制并部署上线”，覆盖 [ADR 0031](0031-dsh-chat-output-limits.md) 中仍保留 USD 0.05/轮、USD 1/日及未授权上线的部分；其余输出、文件、权限和恢复边界保留。阶段、验证和部署结果统一见 [ROADMAP](../ROADMAP.md#p64dsh-输出上限与截断处理)。

## 决定

- 新增严格服务端配置 `models.cost_limits_enabled`，默认 `true` 保持既有安装兼容；本次生产明确设为 `false`，同时将 `chat_max_output_tokens` 设为 256000。模型与插件没有修改该配置的接口。
- 关闭时，不再检查每轮/每日金额，也不按金额缩减聊天输出。聊天、工作总结、压缩、网页、M2 解释、扩展生成和插件目标续跑使用同一策略；保留每日最多 100 次、每轮动作/交换数、超时、授权、取消、价格快照有效期及未知先核对。
- 金额不设限不等于费用为零。调用前仍登记有限费用预估：聊天按 32768 输入/配置输出上限估算，解释与扩展按各自 token 上限估算。有效用量照常结算，未知费用不清零或重算，历史账本完整保留。默认价格下 256000 输出聊天的保守预留为 317031 microunits；这是审计预估，不是重新设定的单轮金额限制。
- 金额关闭不绕过输入/输出结构与使用量校验，仍拒绝超过实际 token 上限的用量；未知执行及同一工作根中的未知调用阻止续跑，不自动重发。
- `GET /api/v1/models/usage` 增加 `cost_limits_enabled` 和实际 `chat_max_output_tokens` 供客户端读取，不修改前端。旧金额字段保留以兼容配置和恢复限额，不代表关闭状态仍在执行该限额。

## 发布方式

以线上固定 wheel `189e7e73…e75b` 为基线，仅覆盖 15 个本次后端文件；`core/config.py` 从该基线作单条件变更，避免带入本地尚未上线的语音字段。保留全部原前端、Node、依赖及 schema026，无新增迁移；独立候选环境与 Linux 固定包测试通过后才暂停、备份和切换唯一 Core。生产配置只改变金额开关及聊天输出上限。失败回退代码/配置，不恢复旧数据库丢弃新账本。
