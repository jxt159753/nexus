# ADR 0002：固定 Node 工具、持久回执与 Windows 进程管理

日期：2026-10-17。状态：在用户明确批准的 P05 内实施；技术验证及用户验收状态见 [ROADMAP](../ROADMAP.md)。

本 ADR 保留 P05 交付时快照；后续 P06 的接入决定见 [ADR 0003](0003-s3-authenticated-link.md)。

## 背景

P05 要求工具仅观察明确本地资源、重复 attempt 不重复执行、进程重启后能恢复结果。使用普通等待线程无法在取消或 Node 崩溃时终止真实工具；只在内存保存结果也无法区分未执行与结果丢失。

## 决定

- 复用 P02 的参数、结果和 v1 命令契约，注册表只含两个固定只读工具；Node 不导入 Core 模块，不增加依赖或通用脚本入口。
- 共享规范化命令摘要函数，绑定目标 Node、任务、attempt、工具动作、授权引用和期限，排除连接会话；本地存储同时比较规范文本和摘要。
- 专用 SQLite 库和 Node 身份绑定，使用版本 SQL、摘要与一致性检查；先 received、再 started、最后有限结果，各阶段先提交再对外使用。只初建或同版本重开，未知旧库明确拒绝；不做破坏性重建。
- 使用数据目录独占锁、单执行槽、10000 条回执容量与有界分页；容量满后拒绝新 attempt，保留去重和恢复事实。
- Windows Job Object 的 KILL_ON_JOB_CLOSE 负责真实进程生命周期。父进程先纳管、再开启输入门，子进程再检查自身归属；没有任意可执行文件或 shell 参数入口。
- started 之后缺少结果的回执恢复为 unknown。Job 结束只证明执行不再运行，不证明从未发生；未确认旧进程结束时阻止新执行。

## 后果与限制

当前提供可组合的本地同步接口；认证连接与传输在 P06，Core 权威验证在 P07，全局控制与对账在 P08。Job 和路径检查不构成不受信本机代码沙箱。首次模式没有升级路径；增加下一版模式时必须先实现并验证一致备份及前向迁移。尚未验证 Windows 10、Python 3.12、其他操作系统及真实网络恢复。

接口细节见 [Node Runtime](../node-runtime.md)，实测证据见 [P05 验证记录](../P05-VERIFICATION.md)。
