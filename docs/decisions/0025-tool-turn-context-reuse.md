# ADR 0025：已完成工具轮次进入后续上下文

- 日期：2026-10-21
- 状态：已采用
- 相关：[ADR 0021](0021-dsh-tools-session-journal.md)、[ADR 0022](0022-dsh-context-compaction.md)

## 背景

用户反馈同一快捷对话中的追问没有上下文。核对实际模型请求后确认：上一轮执行过 `web_search` 工作步骤，`context_count=0`，Core 只发送了当前一句。旧规则把含工具步骤的轮次视为不可自动复用，用户明确选择改为自动带入工具轮次。

## 决定

1. `chat_compaction.reusable_turn()` 不再因 `work_grant_id` 或 `chat_work_steps` 拒绝普通完成轮次。
2. 已完成轮次的用户输入和最终回答进入后续普通上下文；真正的工作结果仍保留在原任务/步骤和模型投影中，不新增第二份长期记忆。
3. **显式记忆引用和显式历史资料引用仍是硬边界**：`memory_refs_json` / `references_json` 非空的轮次仍不自动复用，必须重新选择并同意。
4. 上下文仍受完整请求大小、字节上限、裁剪和压缩规则约束；不会因本决定无限扩大。
5. 这是一次明确的隐私边界变更：工具输出（可能包含工作区内容）可能被自动再次发送给模型。用户已明确选择接受。

## 影响

- 普通追问可以延续工具执行后的最终回答，不再要求重述。
- 显式记忆/引用同意、工具执行授权、审批和费用边界不变。
- 上下文裁剪可能优先丢弃旧工具轮次；原工具证据和审计记录仍保留。
- 需要在架构和操作文档中移除“工作结果永不自动进入普通历史”的旧表述。

## 验证

- 新回归用例：完成一个 `get_node_status` 工具轮次后追问，`context_count=1`。
- `tests/test_chat_work.py` 通过。
- 生产部署与真实追问验证另记。
