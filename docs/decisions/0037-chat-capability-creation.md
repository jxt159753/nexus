# ADR 0037：会话中的插件与 Skill 创建

日期：2026-10-23。状态：按用户明确请求采用；具体实现、自检和部署状态见 [P77](../ROADMAP.md#p77-chat-creation)。本决定只覆盖当前会话内的候选创建，不批准 ADR 0035 的持续自迭代或源码发布。

## 决定

复用原聊天函数选择、工作步骤、版本库及验证器。用户明确要求创建，或当前任务确实缺少可复用能力时，模型可提交候选；先检查已有目录，已有工具能完成的一次性工作直接执行。组合既有工具用 Skill，新增 Python 处理用插件。必要性属于模型判断，权限和成功结论属于 Core，不使用字符串关键词触发或第二个分类/生成模型。

新增 `skill_create({reason,skill})`，严格接收既有 SkillGeneration，至少一项完整步骤测试；由 Core 分配 revision。Markdown、步骤和契约持久存入原表，原 Skill 测试器使用可信替身验证，不执行宿主命令。相同候选/节点可复用，冲突不能覆盖版本。本入口不自动修改已存在 Skill。

原 `plugin_install` 继续独立 runsc 测试。新候选保存及隔离/替身验证在有效 standard 会话范围内免第二次确认，减少“已经要求创建却又确认创建”的往返。read、计划模式、旧等待确认、取消/撤销、恢复 hold、额度和静态范围仍检查；候选事务先记录操作额度，测试和自动启用前重查。

创建与启用分开：插件 normal 需要批准具体测试版本，full 保留既有自动启用规则；Skill normal/full 都需要原版本批准。不会为了立即使用新 Skill 而自动批准，也不借 Shell 写文件绕开版本库。失败和测试不可用保留候选，不变成可执行能力。

## 持久化、边界与结果

使用 step_id 派生幂等请求号，原 extension_requests 记录工作步骤来源，原 model_calls 保存会话费用。创建不调用独立 Extension Provider，不扩大原 4 动作/5 交换、32 KiB 完整请求、调用次数及外发范围。创建工具只在对应配置启用时提供，模型不能打开配置。

停机/取消后原请求与候选可查询；重启继续走原恢复 hold，需要明确继续且原范围有效。Skill 结果返回版本、摘要、测试/批准/启用状态及 `execution=not_run`。`approval_required` 与 `approval_available` 分别表达尚未获批、测试通过后可批准，不能将测试失败解释为免批准。测试成功和步骤成功只表示候选及列明验证成立，不表示用户原业务目标完成。

不新增数据库迁移、第三方依赖、Node 执行协议或前端实现。前端复用工作步骤与原版本审阅，具体交给用户控制 DSH 的要求见[聊天工作](../chat-work.md#在会话中创建插件或-skill)。实际模型是否稳定地选择和编写正确候选需要真实模型验证，合成 Provider 和替身测试不证明这一点。
