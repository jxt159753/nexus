# ADR 0017：项目上下文与受控基础工具

日期：2026-10-20。依据：用户要求完成 M6 并增加读写文件、查找文件与命令行，随后明确选择“指定工作区＋写入审批＋受控命令”。实施及验收状态仅维护在 [ROADMAP](../ROADMAP.md)。

## 决定

复用现有 Core 权威、projects / memory_entries / conversations / tasks、Harness、审批和 Node 回执，不创建另一套记忆库、模型循环或执行器。M6 配套页面沿用原生 HTML/CSS/JavaScript，不增加依赖。

迁移 014 给会话增加不可变的可选 project_id，给轮次增加实际记忆引用快照，新增有界待办及修改事件。迁移 015 在同一迁移事务内扩展 grants 的工具约束，逐列原样保留旧授权；没有给旧身份新增任何授权。迁移前沿用一致备份，不能用新库覆盖旧库。

## 项目与记忆

- 项目会话分别查询；任务由聊天或流程产生时继承会话项目，创建事务再次检查项目归属。项目关联仅组织记录，不扫描目录。
- 保存、替代、撤销沿用明确同意接口。在聊天中编辑内容、类型、来源、有效期后确认保存；替代条目不得跨项目，聊天来源必须对应同项目的真实轮次。
- 本轮最多选 8 条、合计 8 KiB 当前有效记忆。预览后单独勾选外发同意，提交与实际调用前重查所有者、项目、撤销/替代/有效期及内容摘要。未选不会发送，保存不等于同意外发。
- 为避免沿用旧同意或从旧回答再次外发已撤销记忆，近期历史遇到使用过记忆的轮次即停止向前选取。后续轮次需要重新选择并同意；原轮次的第二次结果解读属于原次明确同意范围，仍重查记忆有效性。已经发出的内容无法撤回，历史快照保留供审计。
- 参考记忆以用户数据角色发送，并标出类型、验证和来源，不赋予系统指令权限。界面在每轮展示真实引用来源；模型文字不能更改保存状态。
- 待办默认为计划/建议，不自动执行。标为完成必须关联同项目、已成功、known、有验证及结果的任务。每次修改保留请求摘要和完整修订快照；每项目最多 1000 项、全局 10000 项，每项最多 200 次记录。

## 基础工具

新增 `filesystem.read`、`filesystem.search`、`filesystem.write_preview`、`filesystem.write` 和 `command.run`。工具版本为 1，使用同步升级后的严格 v1 联合契约；旧节点只能使用其原能力，不能向旧版发送新动作。生成 Tool 的 v2 隔离协议不变。首版从“任务”页面明确选择这些操作；聊天和生成 Skill 的自动工具目录仍限原能力，不自动获得新文件或命令权限。

有效能力仍是 Core、身份授权、Node 注册和本地策略的交集；新工具均需逐次任务审批。配置样例仍只启用原两个工具。任何文件内容或命令输出不会自动外发模型。

文件只接受 workspace 和规范化相对路径，拒绝绝对路径、UNC、`..`、反斜杠、ADS、设备名及不规范组件。Windows 逐层持有禁止删除/改名共享的目录句柄；最终读取以 OPEN_REPARSE_POINT 打开并核对普通文件，拒绝符号链接、junction、reparse point 和硬链接。名称搜索不跟随链接，最多扫描 2000 条、8 层并返回 100 个匹配；深度、数量或可表示路径截断均说明不完整。

读取仅支持 UTF-8，文件最多 1 MiB，单次正文最多 8 KiB；返回全文摘要、实际大小和截断状态。写入仅支持最多 12000 字节 UTF-8，父目录必须存在。先运行预览任务，返回旧/新摘要和有界差异；写入提交事务检查同用户、节点、项目、路径、完整新内容摘要及成功预览。写入动作另需审批。Node 两次核对旧摘要，创建时使用不覆盖已有文件的原子操作；替换使用同目录临时文件和 Windows ReplaceFileW，保留目标 ACL，不忽略合并错误；结果前再读回校验。

本机非协作编辑器在最后摘要检查与替换间仍存在极小竞争窗口；这是受信用户本机的文件操作，不是抵御恶意本机管理员的文件系统沙箱。不应在外部程序持续修改的文件上并发写入。进程中断可能留下专用临时文件；不自动扫描删除用户目录中的残留，也不声称失败能够撤销已发生的写入。

命令模板由管理员在 Node 显式配置：绝对可执行文件、文件 SHA-256 与固定 argv；Core 同时登记模板摘要，注册时取摘要交集。API 不接受 shell 文本、任意参数、环境变量或工作目录。禁止 shell 程序和 `.cmd/.bat/.ps1/.sh` 模板；执行用 shell=False，最小环境不继承 Node/模型凭证。工作目录固定 workspace，最多 8 秒，stdout/stderr 各 8 KiB，超限结束调用。进程及后代继承原 Windows Job，取消、超时及 Node 崩溃使用原停止/对账机制。记录退出码；工具成功仅表示取得并验证了这次命令运行记录，退出码非零不能称为业务成功。

**固定工作目录不是操作系统沙箱。** 管理员配置的程序及其项目脚本可以产生程序本来拥有的文件或网络效果，因此只应登记已理解且明确允许的固定命令。没有开放模型生成命令，示例不登记任何实际命令。修改模板、程序、授权或资源策略后重新核对摘要并审批。

写入与命令最多一次 attempt。重传仍使用原 attempt_id 并由回执去重；断线/重启结果未知时只对账，不自动重新执行，不把 unknown 改成“没有发生”。

Windows API 参考：[CreateFileW](https://learn.microsoft.com/zh-cn/windows/win32/api/fileapi/nf-fileapi-createfilew)、[ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。这些 API 的使用不扩大本项目的隔离保证。
