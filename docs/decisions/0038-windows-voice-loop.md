# ADR 0038：Windows 语音闭环、流式播报与实际停止

日期：2026-10-23。状态：已采用；技术和用户验收状态见 [ROADMAP](../ROADMAP.md)。本轮用户明确授权 Codex 完成 Windows 前端、原生桥、语音运行时、Core、部署及安装包，允许少量付费和真人测试，开麦前提醒配合；音色最初选择C参考，随后按试听反馈改为原创轻透空灵女声，最终选择与真人确认见P63。

## 决定

1. 保留独立 `nexus-voice` 设备进程和 Core 媒体代理。Core 调用 Fun-ASR 与 CosyVoice 3.5 Flash，Windows 仅负责采集、AEC3/降噪、本地 KWS、播放和实际停止。LLM 与工具仍只经过原 ChatService/Harness，不另建推理循环。
2. owner 在原 Cookie/Origin/CSRF 下准备会话，将外发同意、设备、会话、请求号和最长30分钟期限绑定；Node 凭证只留在原生桥和子进程。连接未完成的会话30秒释放。语音工具选项使用文字聊天的目录、普通/完全模式、审批及执行证据。
3. 上行16 kHz PCM16，默认40 ms分包；下行22.05 kHz PCM16，以 `NXV2 + uint32 generation + end flag` 帧头标记代次/结束。替代早期 MP3 方案，避免另加设备解码与缓存层；带宽约609 kbps加协议开销，单会话有界队列和背压。
4. Chat 增量按短句进入同一条双向 TTS 任务，接收与发送并行。代码、链接不逐字朗读，详情保留聊天界面；最多播报1000字符、180秒。结束帧后设备等待真实播放缓冲和输出延迟耗尽，再回完成证据；Core 不凭合成结束即恢复收听。
5. AEC 远端参考来自实际输出回调。近端语音连续约120 ms触发本地静音/丢弃旧代次，Core 关闭旧TTS并取消原聊天/工具工作；保留有界预卷减少首音丢失。无AEC时明确半双工，保留手动打断。默认设备端点变化会结束会话，需用户重新开始。
6. 停止先关闭本地设备，再发送网络请求。退出、断线、撤权、暂停、Core重启均不自动开麦或重放。Core 仅在真实设备回执到达后记录采集/播放已停；未收到时明确停止证据未知。
7. 主动播报和主动收听分别勾选，默认关闭，限本会话本设备唤醒待机；北京时间22–08免打扰、每日最多10次。既有本会话新提醒事件先持久认领再播报，重复或错过的事件不重播；无独立收听许可不启动云端ASR。
8. 音频调用先预留、再记录估计或未知费用；未知不归零。原始录音不落盘，partial不持久化，final进入原聊天记录。读回已有错误自然语言说明，未知执行解释后结束语音，不自动重做。

## 交付与后果

Windows安装包包含独立语音程序和按锁定摘要校验的KWS模型，保留原Node身份、回执和冻结程序。生产以实际线上固定wheel为基线，只合入语音增量；027迁移只新增voice表。后续并行上线的性格、自动记忆及schema029保留，最终两文件修正以该实际线上版本为基线。回退包保留当前授权与记忆撤销策略，可读当前数据库，回退不覆盖新业务数据。

PCM增加公网带宽，AEC/唤醒和端到端延迟仍受设备、房间与供应商影响；程序测试和合成音不能替代真人、声学延迟和长时间误唤醒验证。完整验收要求见 [语音验收标准](../realtime-voice-acceptance.md)。
