# ADR 0044：累计调用与金额额度可全部关闭

状态：2026-10-24 用户明确批准实施、部署及提交 GitHub；发布结果统一记录于 ROADMAP P89。

P87 实测已正确检查电脑 Windows-MCP，但总结前触发旧每日100次额度。用户要求取消所有累计调用和金额限制，而非提高固定上限。

- 保留既有 `models.cost_limits_enabled`，新增 `models.call_limits_enabled`；旧配置缺省为 true 以兼容既有受限安装。示例与本次生产均显式 false，模型和插件没有修改入口，不能自行恢复额度。
- 次数关闭覆盖模型及网页共享日账本、单轮工具动作／交换、工作授权累计操作、目标续跑轮数、语音调用／轮数及主动播报日计数。工作授权保存 `operation_limits_enabled`，父子设备授权共用根计数；关闭后计数继续增长，不影响身份、资源范围、审批、撤权和期限。
- 金额关闭覆盖任务、每日及持续目标根费用；语音 ASR／TTS 累计用量额度也关闭。过期价格快照保留原日期用于估算审计，不再阻止调用，不宣称旧价格是最新报价。完整结束但账单未知的调用保留 unknown，不当作免费；仍在执行或执行结果未知的调用不被重新派发。
- Schema036取消 `chat_work_steps.step_index` 的16上界并添加授权开关列；迁移保留标识、原字段及外键引用。升级前必须备份，回退包须能识别schema036，不能拿旧备份覆盖上线后的账本。
- 每批4个工具调用、单插件调用的8个子调用、请求／输出／存储容量、执行超时、授权期限和用户停止仍属于传输与执行边界，不限制累计任务调用。明确设置的提醒次数属于用户任务语义，保持不变。关闭额度不构成新目标授权。
- `GET /api/v1/models/usage` 返回两个额度开关；`work_grant` 增加 `operation_limits_enabled`。客户端无需更新即可继续聊天；本次不改前端。

验收需要超过原阈值的真实运行路径替身测试、迁移旧记录／外键核对、保留取消及权限负例、固定包部署与手机入口真实模型完整答复。不得以单次成功冒充无额度路径、完整桌面动作或真机体验均已验证。
