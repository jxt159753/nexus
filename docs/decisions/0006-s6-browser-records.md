# ADR 0006：同源浏览器、持久通知索引与显式记忆

日期：2026-10-18。实施依据：用户“完成S6”。状态：已实施，技术交付及用户验收见 [ROADMAP](../ROADMAP.md)。不改变单活 Core、两个只读工具及零真实模型调用边界。

已有 Harness、会话、审批、控制和任务历史可复用。浏览器需要统一恢复任务和控制通知，并管理用户明确同意的信息；Node 不参与认知记录。

- 原生静态客户端随 Python 包同源提供，不引入前端框架、构建链或外部资源。Cookie/Origin/CSRF 沿用现有边界；CSRF 从高熵会话令牌派生并仅存摘要，使刷新页面可恢复会话。
- SQLite 触发器在原任务/控制事务内追加统一 `client_events` 索引。独立浏览器连接有界轮询、排队及超时，慢客户端不占调度锁。不引入消息服务，也不在内存维护第二套任务权威。
- 事件是状态失效通知，附最新任务快照及当前 revision。null/无效游标明确要求 HTTP 快照，有效游标回放后继续读取同一持久流。浏览器按成功处理进度推进游标；页面重载重新查询，避免依赖丢失的缓存。
- 明确保存请求在事务中绑定完整内容和同意记录；替代、撤销、过期保留独立字段与可查历史。verified 是带依据的用户声明，不自动采信工具输出。任务/记忆可选项目关联不扩大执行范围。
- 路由随任务创建原子记录，历史补记不捏造耗时。禁用 Provider/DecisionModel 无网络代码；model_calls 为零行时才显示零调用，模型成功率不适用。

代价：250 ms 轮询及有界分页增加少量 SQLite 读取；仅面向单用户、最多 10 个浏览器连接。海量历史、跨库游标身份、长期归档、记忆物理删除及真实模型预算均需后续单独设计。当前没有自动清理任务或个人记忆。

接口及恢复细节见 [S6 说明](../s6-browser-records.md)。远程 TLS、Android 真机及完整 M1 验收属于 S7，不由本决定提前实施。
