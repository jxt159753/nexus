# ADR 0015：M4 持久沙箱命令与 WSL2 KVM 执行端

日期：2026-10-19。用户明确要求完成 M4，随后批准本机 WSL2 沙箱、专用用户的 KVM 设备权限、完成后的服务器部署和 GitHub 上传；另逐次批准最多一次 USD 0.05 的合成 DeepSeek 生成验收。实际状态与结果见 [ROADMAP](../ROADMAP.md#m4自定义工具与流程)，本文件不代替能力版本批准。

## 决定

1. 保留唯一云端 Core；本机 WSL2 作为独立 Sandbox Node，Windows Node 仍只执行原有两个工具。现有生产 Core 宿主不运行生成代码，不安装 runsc。
2. 本机 systrap 启动失败而 KVM 固定可信探针成功，因此在用户批准后明确配置 `platform='kvm'`。不自动切换平台，不降低为普通子进程。绑定 runsc 安装摘要（含外置组件）、镜像树摘要、节点和固定执行策略。
3. rootlesskit 在专用非特权宿主用户下提供用户、挂载与网络命名空间。父 systemd cgroup 实际强制 1 CPU、512 MiB、64 个任务与零 swap；每次运行前核对。OCI cgroup 声明不作为 rootless 强制限制的证据。生成程序使用 UID 65534、无 capabilities、只读根与代码、无外部网络及 16 MiB tmpfs。
4. 迁移 012 保留原有业务字段，新增 Skill 请求幂等身份、持久测试流程与沙箱执行日志。测试与业务命令都先提交再发送，Core 提交结果再确认；重连查询原身份，不重发成新执行。对账最多 64 次，计数跨重启保留。
5. Tool 结果恢复仍通过可信控制器校验。只能确认已停止却找不回结果时保留结果未知，不伪造成功；取消在停止状态尚未确定时继续显示处理中。原有 v1 协议与目录审批不放宽。

## 取舍

WSL 免于新增服务器费用，但依赖本机开机、WSL 存活及网络。systemd 服务不保证 Windows 始终保持 WSL 运行，启动方式必须维持前台 WSL 会话；云端 Core 不因此形成第二个认知中心。不同 WSL 内核和 KVM 版本需重新实测，不能推广为所有 WSL 都兼容。

宿主资源压力可能终止整个 Sandbox 服务。容器 ID 与接收/结果回执因此必须在启动前后持久化，重启先清理和核对。扩大资源、挂载、网络或宿主权限仍需重新审阅，不能由生成代码或模型建议修改。

详细接口见 [v2 协议](../m4-extension-protocol.md)，部署约束见 [WSL2 说明](../m4-sandbox-wsl.md)。
