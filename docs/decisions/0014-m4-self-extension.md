# ADR 0014：受约束的 Tool/Skill 自扩展版本与独立沙箱

- 状态：首版实现；真实 sandbox 隔离待独立主机实测
- 日期：2026-10-19
- 关联：[ARCHITECTURE 第 15 节](../ARCHITECTURE.md#15-自扩展tool-与-skill-方案)、[M4 工作文档](../M4-DSH-WORKORDER.md)、[v2 协议](../m4-extension-protocol.md)

## 决策

1. 自扩展产物是不可变 `extension_versions`；生成、测试、批准、启用和业务执行分开存储。候选由 Core 分配 `capability_id`/revision，模型不能覆盖内置命名空间或已有 revision。
2. `artifact_digest` 覆盖 manifest、源码/说明、步骤、候选测试、依赖、验证配置和环境绑定；修改任何一项都产生新版本。批准绑定摘要、最新通过测试、环境、节点/资源、参数摘要、策略版本和期限。
3. 生成复用全局 `model_calls` 账本与单并发；每根扩展请求最多一次调用、4096 输出 token、30 秒，默认禁用。开发夹具只在显式配置下使用，并走同一解析/摘要/测试/批准链路。
4. Skill 仅支持 1–3 个顺序步骤，步骤引用固定内置工具或固定扩展 Tool 版本；只允许字面量和前面已验证结果的显式字段引用，禁止循环、分支、递归、嵌套、动态名称和表达式。
5. Tool 只接受显式有界 JSON 和单一 Python 标准库源码；可信控制器维护固定用例并通过 v2 协议在 runsc 沙箱执行。Core 不导入候选，也不采信候选自报通过。
6. v1 协议和 Windows Node 两工具保持不变；生成 Tool 只走独立的 `/ws/v2/sandbox` 和登记授权的 Sandbox Node。
7. 缺少合格沙箱时，测试状态为 `unavailable`，批准与执行被服务端拒绝；不得退回普通 subprocess 或 Windows Job。
8. 独立复核后，Core 采用共享的批准校验及最终发送门：停用/取消与发送共用 Harness 锁，步骤关联与任务创建同事务。业务 Tool 的 execution_id 取持久 tool_run_id；无法确认停止时保留 unknown 并阻断，Node 等待所持执行清理后释放数据目录锁。输出采用运行期间有界管道，禁止先向宿主文件无限输出再事后检查。

## 后果

- 优点：生成、测试、批准与执行证据可分别审计；版本不可变，旧批准不能复用到新内容；默认关闭并保持 M2/M3。
- 代价：每次修订需要新测试/批准；真实 Tool 示例在专用 Linux/runsc 主机验证前不能完成批准，因此 P23/P24 的生成 Tool 实际隔离验收保持未完成。
- 测试替身只证明控制器、协议和拒绝路径；不证明 runsc 隔离、宿主限额或实际进程清理。

## 未决

实际 Sandbox 主机的 runsc 兼容性、镜像构建/摘要、宿主 cgroup 限额、网络/设备/元数据负向测试和进程清理，必须由 owner 提供专用环境并另行授权后完成。
