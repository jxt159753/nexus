# ADR 0047：通过会话注册设备与修改节点

状态：2026-10-25 用户批准实现、前端、验证、Core 部署和 APK 发布；实际进度见 ROADMAP P95。

Android 安装实例先在已登录 owner 会话中绑定独立的安装证明和 Node 凭据。两种随机凭据由原生端生成并用 Keystore 加密保存，Core 只存摘要。准备绑定不创建 Node 身份、不授予工具权限；已有 Node 必须证明持有原凭据，不能覆盖身份或回执。

Core 在会话提交入口识别用户本轮直接发出的完整设备管理指令，包括注册、名称、备注和 Android 权限开关。此控制语法不使用模型，不读取历史、附件或工具结果来决定授权；问句、引用和否定句不能授予权限。不能完整识别配置时不做部分修改。普通自然语言仍走原有聊天流程。管理“此设备”必须同时通过 owner Cookie/CSRF 和安装证明；仅传 `client_node_id` 不构成设备证明。

身份、节点策略、指定节点的 owner 授权、节点授权、名称、审计和会话结果在同一数据库事务内提交，随后更新单活 Core 的运行策略。`device_owner_grants` 限定 owner、节点、工具版本及资源，避免给新平板授权时扩大其他节点权限。工具仍取身份、静态策略、节点声明、本机策略和双方授权的交集。模型和插件不能调用注册接口替自己授权。

新设备未指定权限时只允许设备状态；文件接收限定 App 私有收件箱。语音许可不自动开麦或同意音频外发；通知摘要还需系统通知读取授权和本机应用允许名单。权限撤销更新策略版本和在线连接范围，语音策略撤销由现有 watcher 停止活动会话。既有执行回执和未知状态继续按原生命周期对账。

原生 App 在查询到注册记录后安装 Node 配置并请求启动前台服务；Android 要求的通知权限仍由系统弹窗完成。重复注册复用同一安装绑定的 Node。会话回复报告配置结果，展示层另外显示当前真实连接状态，不将“已保存”当作“已连接”。用户停止后不会因普通轮询自动重启。

数据库迁移 039 新增绑定、受管节点配置、节点范围授权和会话变更记录。静态 TOML 节点仍兼容，受管策略启动时从数据库恢复；名称和备注也可用于其他平台节点，当前在线权限配置只面向 Android。回退运行包包含同一迁移以保留新数据，恢复旧功能时不删除新身份、权限和历史；再次升级可重新加载受管节点。
