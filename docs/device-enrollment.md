# 在会话中注册与管理设备

在新版 Android App 登录你的 NEXUS 后，在聊天中发送：

> 注册这台手机

App 会自动生成并保存独立设备身份，Core 登记名称和指定权限，随后 App 启动 Node。无需复制 UUID、节点令牌或编辑服务器配置。如果 Android 弹出通知权限，请按系统提示选择；状态显示“设备已连接”才表示 Core 已观察到连接。

不指定功能时默认只允许设备状态，并主动询问需要开启哪些功能。在同一手机、同一会话紧接着回复“语音和接收文件”即可选择；也可以说“打开语音和接收文件”，或直接去设备页操作本机开关。仅展示能力不代表授予权限。重复注册使用同一身份，不创建重复节点。重新登录或升级保留身份和执行回执，不要通过卸载清数据处理执行结果未知的问题。

后续可在会话里说：

- 将客厅平板改名为书房平板
- 这台手机改名叫红魔
- 将书房平板的备注设为放在书桌上
- 开启书房平板的接收文件权限
- 关闭书房平板的语音权限
- 开启此设备的通知摘要权限

支持设备状态、接收文件、语音、通知摘要、无障碍操作、屏幕视觉操作和手机文件七项权限。文件接收只到 App 私有收件箱；语音仍需主动开麦和音频外发同意；通知摘要需在设备页设置应用允许名单并打开系统通知读取权限。手机操作和文件需本机开关及系统服务／目录授权；直接打开本机开关就会同步 Core。名称最长 40 字、必须唯一；备注最长 200 字。电脑节点当前可改名称和备注，Android 权限词不能用于扩大电脑 Shell 或文件访问范围。

“此设备／这台手机／这部手机／我的手机”只适用于有安装证明的原生 Android 会话。网页和旧客户端可以按已有节点名称修改信息，不能把浏览器注册成执行节点。支持“帮我注册一下节点”“登记本机”“给这台手机开启语音”等表达，注册后的名称与权限不强制使用固定逗号句式。紧接注册问题的纯功能列表仅在同一会话、同一安装证明下识别，重试保持原结果；问句、引用、否定或混合不明配置不直接授予权限。仍采用确定性识别，不宣称任意自然语言都能识别。

Android 0.1.15 的本机无障碍、视觉、文件开关，以及保存后的收件箱／通知应用名单自动同步到 Core。页面区分待同步、失败及已同步；未登录、离线或后台暂停期间保留本机选择，登录／重连／回前台后核对。重复的旧选择不会恢复之后在 Core 撤销的权限；此时显示 Core 已另行调整。初次未选择收件箱时不从 Node 默认能力推断授权。

接口：owner Cookie/CSRF 下 `POST /api/v1/device-clients` 绑定安装证明，`GET /api/v1/device-clients/{client_id}` 使用 `X-Nexus-Device-Proof` 查询状态。会话提交携带 `device_client_id` 和相同证明头；Node 凭据只进入原生绑定接口，不进入聊天文本、模型输入或聊天结果。管理回合有 `device_change` 字段，`online` 是实时观察，不能作为历史执行证据。其他客户端无需新增字段即可继续使用原接口。

新增 `PUT /api/v1/device-clients/{client_id}/permissions` 使用相同 owner 会话、CSRF 和安装证明。请求为 `{"revision":1,"permissions":{"accessibility":true,"files":false}}`；权限键只允许上述七项的英文标识，值必须是布尔值。客户端发送全部已知的本机选择，未选择过的项可省略；每次本机选择变化递增版本，先保存再发送。Core 将最新快照、策略、节点范围授权与审计事务化保存；相同版本同内容只读回，过期版本或同版本不同内容返回409。只有相对上一份本机快照改变的项才更新权限，重复快照和无关开关不能覆盖远端撤销。GET／PUT 返回 `permission_sync` 确认快照；重启后继续核对。schema044只新增快照表，旧客户端和 Node hello 不改变行为。

设计与边界见 [ADR 0047](decisions/0047-conversational-device-enrollment.md)，实际发布和验证见 [ROADMAP P95](ROADMAP.md#p95-device-enrollment)。
