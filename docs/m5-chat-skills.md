# 在聊天中完成多步任务

本说明描述 M5 的操作与接口。具体版本、本地验证、上线及验收状态见 [路线图](ROADMAP.md#m5从聊天完成多步任务)，技术选择见 [ADR 0016](decisions/0016-m5-chat-skills.md)。当前云端版本是否已包含此入口须以路线图为准。

## 提出目标与确认计划

1. 在“聊天”中新建会话，允许工具建议并选择目标设备。
2. 点击“查看此设备可用流程”，展开查看本次目录。只列出有权限、已测试、已批准且启用的固定版本，最多 8 个。
3. 勾选“本次允许将以上流程目录发送给 DeepSeek 并建议多步流程”，输入例如“给我做一份工作区概览”，再发送。目录随本轮输入和选定上下文一并外发；设备身份、凭证、代码和旧执行结果不会因此自动发送。勾选在发送后清除。
4. 查看建议卡中的流程、版本、设备和步骤。每步可展开“设备与数据范围”，目录步骤会注明另需审批。没有匹配能力时不会临时生成或执行新代码。
5. 有缺少的参数时填写表单，点击“核对参数并更新计划”。修改参数后必须重新核对；旧确认不能用于新参数、版本或权限范围。
6. 核对后点击“确认以上计划并执行”。确认前没有流程运行或设备执行；重复点击或重试同一确认只返回同一运行。
7. 目录步骤仍须点击任务卡中的“批准本次任务”，不能用流程确认代替目录审批。

流程最多 3 个顺序步骤，只复用已启用的固定工具版本。流程中的说明文字、模型回答及测试通过标志都不能自行授予设备权限。

## 查看进度与停止

会话卡显示当前步骤、等待设备、等待目录审批、失败、取消及未知结果，原任务卡仍可查看执行记录。流程运行期间暂不接收本会话下一轮消息，避免尚未完成时重排结果上下文；其他会话不受此约束。

- “取消整个流程”：请求停止当前实际执行并阻止后续步骤。收到 Core 的最终核对前会显示正在取消；已经完成的步骤结果保留。
- “停止回复”：关闭模型交换，不代替取消流程。
- 全局“暂停派发”：阻止新的派发和模型调用，已经执行的步骤可完成。

刷新、断网或重新登录只读取 Core 保存的运行、任务及结果，不自动再次确认、调用模型或重跑已完成步骤。无法确认的执行明确显示未知；取消或超时不保证已有操作从未发生。

## 完成与解读结果

实际成功需要每步工具证据和验证。成功后无需模型也能查看结构化结果；需要文字解释时：

1. 点击“预览可发送的结果”。
2. 按步骤选择白名单结果；改选后更新预览，核对完整外发数据。原输入、当时选定的上下文和实际确认的流程输入也会发送。
3. 点击“同意发送这些结果给 DeepSeek 并生成最终回答”。

流程首版使用执行后的结果预览，不提供默认自动回传。系统信息限于原有字段，目录只包含资源别名、直接条目的名称/类型及截断状态；JSON 统计工具只包含已验证的 counts/total。不会发送文件正文、绝对设备路径、凭证或原始错误。单次结果最多 8 KiB，裁剪和省略字段会明确显示。

目录被截断时，统计只代表已返回条目；解读不能改写失败或未知状态，也不能将 `skill_steps_verified` 夸大为独立观察。失败、取消、未知或证据不匹配的流程没有结果解读入口。

普通建议占本轮一次模型调用，解读最多追加一次，合计沿用 USD 0.05 上限及 UTC 每日 USD 1 的共享账本。第一次费用未知、预算不足、价格过期、权限变化、预览过期或已有后续会话消息时停止追加调用。执行、进度轮询和恢复不调用模型。

## 接口与升级

沿用原聊天与流程 API，新增接口如下。HTTP 认证、Origin 和 CSRF 检查保持一致。

| 接口 | 内容 |
| --- | --- |
| `GET /api/v1/chat/skills?node_id=...` | 返回可外发的 skills 和绑定设备的 skills_digest；不调用模型 |
| `POST /api/v1/chat/conversations/{id}/turns` | 在原请求中增加 allow_skills=true 和预览得到的 skills_digest；同时要求 allow_tools=true、node_id 和本轮模型同意 |
| `POST /api/v1/chat/turns/{id}/plan-preview` | 正文 input 对象；验证参数并返回新计划和 proposal_digest；不执行、不调用模型 |
| `POST /api/v1/chat/turns/{id}/action` | 原确认/拒绝接口；流程确认返回 skill_run，原单步动作继续返回 task |
| `GET /api/v1/chat/turns/{id}` 及会话历史 | 返回 skill_plan、skill_run_id 及已有运行快照；详情另含本轮实际目录快照 |
| `POST /api/v1/extensions/runs/{id}/cancel` | 原流程取消接口，等待真实执行结算 |
| 原 result-preview / result-consent | 流程使用步骤 ID 选择结果；其他摘要、同意、费用和幂等语义沿用原接口 |

迁移 013 在 chat_turns 增加目录/计划快照及运行关联，在 model_calls 增加可空运行关联；不改写 001–012。升级前沿用一致备份、摘要检查和外键校验。旧聊天、请求快照、工具证据及未知费用保留，旧记录不会因此自动执行或外发。回滚应用前需要核对数据库兼容性，不把删列、清库或重新建库作为回滚方法。
