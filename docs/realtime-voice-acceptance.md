# NEXUS 实时语音验收标准

配套设计：[实时语音扩展](realtime-voice.md)。本文件只定义**怎么验、验什么、什么算通过、证据放哪里**；不表示功能已实现或已验收。状态与批准记录仍以 [ROADMAP](ROADMAP.md) 为准。

> **2026-10-22 选型更新**：ASR/TTS 主路径改为 Core 代理百炼（`fun-asr-realtime-2026-02-28` + `cosyvoice-v3.5-flash`），音频经 Core。本文件中“本地 ASR/TTS”的模型/资源项仅适用于离线备选；主路径新增公网/Core 媒体代理验收（见第 16 节）。原始麦克风音频会经 Core 到阿里云；Core 不落盘，但供应商保留按条款处理。

2026-10-23 实现口径：[ADR 0038](decisions/0038-windows-voice-loop.md) 为当前行为。上行默认40 ms，服务端句末判定；下行22.05 kHz PCM16/NXV2，设备实际drain后确认。待机KWS时麦克风保持开启但不上传；主动播报无独立listen许可不启动云端ASR。按钮静音超时结束关麦，唤醒会话则回本地待机。重连不自动开麦。原离线指标、100 ms分包、双重端点和“主动播报绝不开麦”应按这些边界解释；真实多轮/打断/长稳标准不降低。

## 1. 原则

1. **真实麦克风优先**：最终验收必须使用真实 Windows 设备、真实麦克风、真实扬声器/耳机和真人说话；文件回放、合成音、虚拟声卡、内录只能作为模拟回归，必须标注 `simulated=true`，不计入最终验收。
2. **分层记录**：单元/集成测试、模拟音频、真实设备、长时间待机、用户验收分别记录，不能互相替代。
3. **可复现**：记录系统版本、CPU/内存、音频设备名、驱动、音量、距离、房间、模型 SHA-256、代码提交、配置摘要。
4. **不夸大**：没有测到的项写“未验证”；失败保留原始数据；不以一次成功代表 p95 或长期稳定性。
5. **停止/隐私是硬门槛**：停止不真实、断线重放、默认写原始录音、唤醒词获得操作权限，任一项失败即不通过，不能用性能分数抵消。

## 2. 环境与设备记录（每次验收必填）

| 项目 | 记录 |
| --- | --- |
| 日期/时区 | 例：2026-10-22，Asia/Shanghai |
| Windows | `winver` / `Get-ComputerInfo`，例：Windows 11 26200 |
| CPU/内存 | 例：Intel Core Ultra 9 275HX，24 逻辑核，31.4 GB |
| 磁盘 | 模型/数据目录所在盘剩余空间 |
| 输入设备 | 名称、WASAPI index、采样率、驱动、是否耳机/阵列/USB |
| 输出设备 | 名称、WASAPI index、采样率、音量、是否耳机/扬声器 |
| 距离/朝向 | 嘴到麦克风 0.5/1/3 m；扬声器到麦克风距离 |
| 房间 | 安静卧室/办公室/有电视背景音；混响/噪声描述 |
| 模型 | 每个文件 SHA-256（来自 `voice-models.lock.json`） |
| 代码/包 | Git commit、wheel/EXE SHA-256、Core schema 版本 |
| 配置 | `voice.toml` 摘要；AEC/NS/AGC、VAD 阈值、KWS 阈值、TTS voice/speed |
| 电源 | 插电/电池、电源模式（最佳性能/平衡） |

> 设备名可用 `Get-PnpDevice -Class AudioEndpoint` 与运行时 `sounddevice.query_devices()` 双重记录；不要只写“默认麦克风”。

## 3. 证据类型与判定

| 类型 | 内容 | 是否可作为最终验收 |
| --- | --- | --- |
| `unit` | 契约、状态机、DND/配额、分段、epoch 拒绝 | 仅技术证据 |
| `simulated` | WAV 回放、TTS 合成音、虚拟声卡、loopback | 仅回归；必须 `simulated=true` |
| `real_device` | 真实麦克风/扬声器 + 真人说话 | 可计入功能/性能 |
| `long_run` | ≥2 h 待机/≥30 min 活动 | 可计入误触发/资源 |
| `user_acceptance` | 用户按场景实际操作并确认 | 最终“已验收”唯一来源 |

证据文件建议 `docs/assets/voice-evidence-YYYYMMDD.json`（脱敏，不含音频/转写正文）与原始日志目录（不入 Git，保留在 `var/voice-evidence/`）。音频证据如必须保留，单独受控存放并说明保留期；默认不提交。

## 4. 功能验收矩阵

| ID | 场景 | 步骤 | 通过标准 |
| --- | --- | --- | --- |
| F1 | 按钮启动 | App/网页点“开始说话” → 说“今天天气怎么样” → 等回答 | 麦克风指示出现；partial 可见；final 成为一个 Chat 轮次；TTS 播放；会话可停止 |
| F2 | 唤醒启动 | 待机说“Hey NEXUS”或“你好奈克斯” → 说一句话 | 唤醒命中；不发送音频；final 前 0 模型调用；进入同一 Chat 会话 |
| F3 | 连续多轮 | 同一会话连续 5 轮追问，不重复唤醒 | 5 轮上下文连续；每轮一个 final/一个 Chat 轮次；无重复回答 |
| F4 | 流式识别 | 说 5–10 秒中文/中英混合 | 至少 3 次 partial 更新；final 与语音内容一致（人工核对）；partial 不落库 |
| F5 | 分段播报 | 让 Core 回答一段 15–30 秒文字 | 首段先播，后续段连续；段间无明显长静音；最后一段完整；无重复段 |
| F6 | 用户打断 | TTS 播放中说“停/等一下/不是这个” | 200–400 ms 内静音；当前 TTS 丢弃；模型请求取消；新语音进入新轮次；旧回答标记 interrupted。**仅在 AEC 可用/未降级时要求**；半双工路径按 F11 单独验收，不承诺语音打断 |
| F7 | 打断后继续 | 打断后立即说新问题 | 不需要再次唤醒；新 final 进入同一会话；旧 TTS 不恢复 |
| F8 | 静音超时 | 激活后 30 秒不说话 | 会话回 idle/standby；麦克风关闭；0 模型调用；不产生空轮次 |
| F9 | 设备切换 | 待机/播放中切换默认麦克风/扬声器 | 运行时发 `voice.device`；不崩溃；活动会话按策略停止或明确报错；不重放旧音频 |
| F10 | 麦克风竞争 | 另一程序以独占模式占用麦克风 | 报 `MIC_BUSY`；不静默录音；释放后可恢复；不自动切未知设备 |
| F11 | 回声环境 | 扬声器 60% 音量播放 TTS 10 分钟 | AEC 开启时自唤醒/误打断计数在阈值内；AEC 不可用时明确半双工降级 |
| F12 | 自我唤醒 | TTS 连续说 20 次“Hey NEXUS/你好奈克斯” | 不触发唤醒；不创建空会话；不调用模型 |
| F13 | 主动播报 | owner 创建 `proactive_speak` grant → 到点播报 | 只播报，不开麦；播报后可查事件；无 grant 时拒绝 |
| F14 | 主动收听 | 同时有 `proactive_listen` grant → 播报后说一句话 | 播报完成后才开麦；8 秒无语音关闭；无 listen grant 时不开麦 |

## 5. 权限与安全矩阵

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| P1 | 无 grant 主动播报 | `VOICE_NOT_GRANTED`；不播报；不调用模型 |
| P2 | 过期 grant | `VOICE_EXPIRED`；不播报/不开麦 |
| P3 | 设备范围不符 | 只允许 grant 中 `device_ids`；其他设备拒绝 |
| P4 | DND 内主动播报 | `VOICE_DND`；不播报；事件记录 `suppressed_dnd` |
| P5 | DND 内用户按钮/唤醒 | 按配置允许或拒绝；默认用户主动激活不受 DND 影响 |
| P6 | 主动收听独立授权 | 只有 `proactive_speak` 时绝不开麦；有 `proactive_listen` 才开 |
| P7 | 日配额 | 达到次数/秒数后 `VOICE_QUOTA`；跨日按 grant 时区重置 |
| P8 | 唤醒不授权 | 唤醒后要求“删除文件/执行命令”不产生工具/写入授权；仍走原 Chat 工作权限与审批 |
| P9 | 模型不能改 grant | 模型/插件无法调用 grant 管理接口；尝试返回 `FORBIDDEN`/不存在 |
| P10 | 跨设备/伪造身份 | 错误令牌、其他 node_id、旧 epoch、跨设备 session 均拒绝；审计记录 |
| P11 | 超大输入/二进制帧 | >16 KiB 消息、二进制音频、超长 partial/TTS 段被拒绝/截断；连接不被拖垮 |
| P12 | 权限变更中会话 | 撤销/修改 grant 立即停止受影响会话；不沿用旧授权继续播报/收听 |

## 6. 停止、断线与隐私矩阵

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| S1 | 按钮停止（播放中） | 本地 200 ms 内静音；麦克风关闭；发 `voice.stopped`；Core 显示已停止/证据 |
| S2 | Core `voice.stop` | 运行时停止真实收音/播放；回证据；不继续 TTS |
| S3 | 全局 pause/cancel_all | 所有语音会话停止；语音 Chat 轮次取消；不新开 |
| S4 | WS 断开（拔网线/关 Core） | 运行时立即本地停止，**连待机 KWS/麦克风也停止**；不重连音频；重连后不重放旧 TTS/播报，旧会话不恢复 |
| S5 | 运行时被杀 | OS 关闭设备；Core 心跳超时→disconnected；不重试旧音频；App 记录退出码 |
| S6 | 停止时模型生成中 | Provider 任务真实取消；费用未知保留；不把未播文本当完成 |
| S7 | 过期 TTS 段 | 运行时丢弃并计数；Core 不重发；不出现“停止后还在说” |
| S8 | 默认无原始录音 | 运行/停止/断线后数据目录无 `.wav/.pcm/.raw`；只有 DB/日志/配置/指标；诊断录音默认关闭 |
| S9 | 转写隐私 | 日志无转写正文；partial 不落库；final 作为聊天记录明确可见 |
| S10 | 设备/麦克风指示 | Windows 麦克风使用指示与实际采集一致；停止后不再占用麦克风 |
| S11 | 会话超时 | 30 分钟/30 轮/单轮上限触发停止；不自动续期 |
| S12 | Core 重启 | 所有语音会话 interrupted；运行时停止；不自动恢复；用户重新激活 |

## 7. 性能测量

### 7.1 指标定义

| 指标 | 起点 T0 | 终点 T1 | 说明 |
| --- | --- | --- | --- |
| 首段可听延迟 | Core 持久化 `voice.final`（或收到 final） | 第一个非静音输出样本可听 | 同时记录“final 生成”“TTS 首样本”“播放写入”“可听估计”；报告分解 |
| final 延迟 | 用户停止说话（VAD 判静音起点） | Core 收到 `voice.final` | 含 600 ms 端点等待；另报“端点后处理” |
| 首 partial 延迟 | 用户语音起始（VAD speech start） | 首个 partial 到达 Core | 不含模型 |
| 打断延迟 | 用户语音起始（AEC 后 VAD） | 输出设备实际静音 | 程序时间戳 + 声学验证（见 7.3） |
| 唤醒响应 | 唤醒词结束（KWS 命中） | 本地提示音/`voice.activate` 发出 | 不含模型 |
| ASR RTF | 音频时长 | 解码耗时 | 报告音频时长/线程数 |
| TTS RTF | 合成音频时长 | 合成耗时 | 报告模型 fp32/int8、线程数 |
| 待机 CPU | 进程运行但无会话 | 采样 30 分钟 | 平均值/峰值；排除模型加载 |
| 活动 CPU/RSS | 会话处理中 | 采样 10 分钟 | ASR+TTS+AEC 同时；记录峰值 |

### 7.2 通过目标（真实设备）

| ID | 指标 | 目标 | 说明 |
| --- | --- | --- | --- |
| L1 | 首段可听延迟（本地段，warm） | p50 < 1.2 s，p95 < 1.8 s | 从 Core 持久化 final 到首个可听样本；不含 DeepSeek 首 token；要求 TTS 已加载；冷启动首次会话另报 |
| L1c | 首段可听延迟（冷启动首次） | 报告实际 p50/p95，不设统一硬目标 | 包含 TTS 加载；若设置 `preload_tts=true` 则按 warm 统计，但待机 RSS 另报 |
| L1b | 首段可听延迟（端到端） | 报告实际 p50/p95，不设统一硬目标 | 从用户停止说话到首个可听样本，包含 ASR final、Core 模型首 token、TTS；必须与 L1 分开，不能只报本地段 |
| L2 | 端点后 final 延迟 | p50 < 150 ms，p95 < 300 ms | 从 VAD 判定端点（600 ms 静音已满足）到 Core 收到 final；不含 600 ms 等待 |
| L2b | 停止说话到 final（含端点） | p50 < 800 ms，p95 < 1100 ms | 从用户停止说话到 Core 收到 final；包含 600 ms 端点等待；必须与 L2 分开报 |
| L3 | 首 partial | p50 < 500 ms，p95 < 800 ms | 从语音起始 |
| L4 | 打断延迟 | p50 < 250 ms，p95 < 400 ms | 从语音起始到输出静音 |
| L5 | 唤醒响应 | p50 < 150 ms，p95 < 250 ms | 本地提示/activate |
| L6 | 待机 CPU | 平均 < 3%（单核折算），峰值 < 8% | KWS+VAD+心跳；不加载 ASR/TTS |
| L7 | 待机 RSS | < 250 MB | KWS+VAD+runtime；模型预加载另报 |
| L8 | 活动 CPU | 平均 < 40%（单核折算），峰值 < 70% | ASR+TTS+AEC；4 核以上 |
| L9 | 活动 RSS | < 700 MB | fp32 TTS + int8 ASR；按实测调整但需说明 |
| L10 | ASR RTF | < 0.3 | 16 kHz，2 线程 |
| L11 | TTS RTF | < 0.5 | fp32，4 线程；首段单独报 |
| L12 | 模型加载 | 待机冷启动（KWS+VAD）< 4 s；会话内 ASR < 2 s、TTS < 5 s；用户激活时 ASR 先就绪，TTS 可重叠加载 | 不含下载；主动播报必须等 TTS 就绪后再开始，不能先播静音 |

> 目标不是承诺；若未达到，报告实际值、瓶颈和是否阻塞发布，不用模拟数据填充。

### 7.3 打断/首段延迟的声学验证

程序时间戳可能低估“实际可听”延迟，需至少一种声学验证：

1. **第二设备录音**：手机/录音笔同时录“用户说话 + 扬声器输出”，用波形对齐测静音起点。
2. **WASAPI loopback**：录制系统输出，与麦克风时间对齐；仅用于测量，不作为运行时依赖。
3. **受控测试音**：TTS 段首加 1 kHz 短标记（诊断模式，默认关闭），loopback 检测标记；不用于正常对话。

报告需同时给出“程序时间戳”和“声学测量”；若只做程序测量，标注 `measurement=programmatic`，不能替代最终验收。

## 8. 唤醒统计

### 8.1 测试集

- 真人：至少 2 名说话人（如只有 1 名，明确记录），每人每个唤醒词 30 次；距离 0.5 m/1 m/3 m；正常音量/轻声；安静/背景噪声（电视/音乐 50–60 dBA）。
- 每个唤醒词单独统计；不同关键词不合并。
- 误触发：待机 2 小时（安静）+ 2 小时（背景语音/电视）；记录每次命中时间、音频片段（如保留）、是否误触发。
- 自唤醒：TTS 连续说 20 次唤醒词；记录触发次数。

### 8.2 记录与目标

| ID | 指标 | 目标/报告 |
| --- | --- | --- |
| W1 | 唤醒成功率（安静，1 m） | 报告 30 次中命中数；目标 ≥ 90%，低于则调阈值/关键词 |
| W2 | 唤醒成功率（3 m/噪声） | 报告实际；不强制统一目标 |
| W3 | 待机误触发 | 报告 2 h 安静 + 2 h 背景的命中次数/小时；目标安静 ≤ 0.5/h，背景 ≤ 2/h（达标与否都如实报告） |
| W4 | 自唤醒 | TTS 20 次中触发次数；目标 0 |
| W5 | 唤醒到 activate | p50/p95；目标 L5 |
| W6 | 待机模型调用 | 唤醒前/待机期间 `model_calls` 增量必须为 0 |

> 误触发目标不是“零”；必须给出计数和统计窗口。一次 2 小时测试不能代表长期，报告限制。

> 账本口径：`model_calls` 只记录 Core 的 LLM/网页调用；本地 KWS/ASR/TTS 不计入该表，另记模型 SHA-256、加载时间、RTF 和资源。待机 0 调用指 `model_calls` 增量为 0，且没有通过语音触发新的 Chat 轮次。

## 9. 资源占用测量

| ID | 指标 | 目标/记录 |
| --- | --- | --- |
| R1 | 待机 CPU | 平均 < 3%（单核折算），峰值 < 8%；30 分钟 |
| R2 | 待机 RSS/私有字节 | < 250 MB；30 分钟；仅 KWS/VAD，ASR/TTS 未加载；若预加载另报 |
| R3 | 活动 CPU | 平均 < 40%（单核折算），峰值 < 70%；10 分钟 |
| R4 | 活动 RSS/私有字节 | < 700 MB；10 分钟 |
| R5 | 会话内模型加载 | ASR < 2 s、TTS < 5 s；用户激活时 ASR 先就绪，TTS 可在用户说话期间加载；主动播报需等 TTS 就绪 |

- 工具：Windows 性能计数器（`\Process(...)\% Processor Time`、`Working Set`、`Private Bytes`）、`GetProcessMemoryInfo`、ETW（可选）；采样 1 s，记录 30 分钟待机/10 分钟活动。
- 报告：平均、p95、峰值；CPU 按单核百分比和系统总核百分比两种口径；RSS/私有字节；GPU（本方案不用）；磁盘 I/O；模型加载时间。
- 环境：插电、最佳性能/平衡分别记录；不要只报“任务管理器看起来不高”。
- 对照：AEC 开/关、KWS 开/关、TTS fp32/int8（仅台架）分别测，说明差异。

## 10. 真实麦克风验收步骤（建议顺序）

1. **准备**：关闭其他录音/会议软件；确认 Windows 麦克风隐私允许；记录设备与音量；安装模型并核对 SHA-256。
2. **待机基线**：启动语音运行时，不激活；静置 30 分钟；记录 CPU/RSS、模型调用、误唤醒；确认无录音文件。
3. **按钮单轮**：F1；记录 partial/final/首段/播放完成。
4. **连续多轮**：F3；5 轮；记录上下文与轮次。
5. **唤醒**：W1/W2；每个关键词/距离 30 次；记录命中/漏检/误触发。
6. **分段与打断**：F5/F6/F7；20 次打断，随机时刻；声学验证 10 次；记录延迟。
7. **回声/自唤醒**：F11/F12；扬声器 60%；10 分钟；记录误打断/自唤醒。
8. **设备/竞争**：F9/F10；切换默认设备、独占占用；记录错误与恢复。
9. **主动权限**：F13/F14、P1–P7；逐项创建/过期/撤销 grant；记录拒绝原因。
10. **停止/断线**：S1–S7；按钮、Core stop、拔网线、杀进程、重启 Core；记录本地静音时间与重连行为。
11. **隐私**：S8/S9；检查数据目录/日志/DB；确认无原始音频、无转写日志。
12. **资源**：R1–R5；待机/活动分别采样；记录环境。
13. **用户验收**：用户按真实任务操作；记录确认语句/日期；开发者自检不能替代。

## 11. 模拟测试与标注

允许的模拟方式：

- WAV 文件回放（16 kHz/48 kHz）替代麦克风；
- TTS 合成音替代真人；
- 虚拟声卡/loopback 替代扬声器-麦克风声学路径；
- 单元测试中的 fake runtime/clock。

要求：

- 每个结果 JSON 顶层 `simulated: true`，并写 `simulation_method`（file/tts/loopback/fake）。
- 模拟结果不得写入“真实麦克风验收”表；不得用于 W1/W3/W4/L4 的最终结论。
- 模拟可用于回归、CI、协议/状态机测试；失败也要保留。
- 合成音唤醒测试只能说明“该合成音可/不可命中”，不能代表真人；本方案第 12 节的台架结果即属此类。

## 13. 通过标准

### 13.1 必须全部通过（硬门槛）

- F1–F14 功能项；P1–P12 权限/安全项；S1–S12 停止/隐私项。F6 的语音打断要求以 AEC 可用为前提；AEC 不可用时必须通过 F11 的半双工/按钮停止路径，并明确记录“不支持语音打断”。
- 真实麦克风证据覆盖 F1、F2、F3、F6、F9、F10、F11、F12、S1、S4、S8；缺一项即“未完成”。
- 待机 0 模型调用；默认 0 原始录音文件；唤醒不产生工具/写入授权。
- 停止后 200 ms 内本地静音/关麦（程序时间戳 + 至少一次声学验证）；断线不重放。

### 13.2 性能门槛

- L1–L5、L6–L9 达到目标，或用户明确接受偏差并记录风险。
- W1/W3/W4 达到目标或给出可解释的偏差与改进计划；不能只报“感觉可以”。
- 资源测量必须有 30 分钟待机 + 10 分钟活动数据；不能用瞬时截图代替。

### 13.3 不算通过

- 只有单元测试/模拟 WAV；没有真实麦克风。
- 只有程序时间戳，没有声学验证打断/首段。
- 只测一次唤醒/打断就宣称 p95。
- 停止只停 UI，实际麦克风/播放仍在。
- 断线后自动重放旧 TTS/播报。
- 默认保存原始录音，或日志含转写正文。
- 唤醒词后直接执行工具/写入，或语音“同意”替代审批。
- 把 Android 协议设计当作 Android 已实现/已验收。

## 14. 重复与回归

- 每次改 AEC/VAD/KWS/ASR/TTS/权限/停止路径，重跑受影响项；AEC/唤醒/打断/停止至少跑一次真实设备回归。
- 固定环境、固定模型 SHA、固定配置；升级模型/依赖需新证据。
- 长稳：建议 8 小时待机 + 1 小时活动作为发布前补充；不强制每次开发，但最终验收应包含至少一次 2 小时以上待机。
- 失败先保留原始日志/时间线，再修复；不删除失败记录。

## 15. 未验证项模板

## 16. 百炼 Core 媒体代理补充验收（2026-10-22 选型）

主路径不再在设备本地跑 ASR/TTS；以下项与前面的本地指标并列，最终验收必须覆盖。

| ID | 项目 | 通过标准 |
| --- | --- | --- |
| B1 | 上行链路 | 设备 AEC 后 16 kHz PCM 持续上行；100 ms/包；丢包/断线时 Core 能识别并停止会话，不静默继续 |
| B2 | Fun-ASR 首包/partial/final | 真实麦克风中文/中英混合；首 partial p50 < 800 ms；final 由服务端句末 + 本地 VAD 共同判定 |
| B3 | CosyVoice 首包 | final 到首帧下行 p50/p95 按实际记录（含 Core→百炼网络）；声音设计 voice_id 正确 |
| B4 | 打断 | 本地 VAD 检测后设备立即静音；Core 关闭当前 TTS task、取消 Chat；不继续下行旧 generation |
| B5 | 公网抖动/断线 | 设备断网、Core 断百炼、Core 重启：停止音频；重连不重放旧 TTS/播报；旧 session epoch 拒绝 |
| B6 | 百炼错误 | 401/403/429/超时/断流分别显示；回退文字；不自动重试已扣费请求 |
| B7 | 费用 | ASR 按音频秒、TTS 按字符预留/结算；日上限/每轮上限生效；未知费用不记零 |
| B8 | Core 资源 | 1 并发会话时 Core CPU/RSS/带宽在服务器余量内；音频转发不阻塞 Chat/任务 |
| B9 | 设备资源 | 仅 KWS/VAD/AEC/编解码；无本地 ASR/TTS 模型；待机 RSS 目标 < 250 MB |
| B10 | 隐私 | Core 数据目录无原始音频；final 转写进入聊天；百炼数据处理/保留范围已向用户披露 |
| B11 | 语音设计 | 用户创建的 voice_id 在 `cosyvoice-v3.5-flash` 下可用；试听样本与生产一致；失败不静默换声 |
| B12 | 小服务器并发 | 默认 1 并发；超出返回 `VOICE_BUSY`，不排队无界；带宽/队列有界 |

- 测试环境必须记录 Core 地域（青岛）、百炼地域（北京/新加坡）、Workspace ID、设备公网类型、带宽、RTT。
- 模拟音/文件回放只能验证协议与链路，不能替代 B2/B3/B4 的真实麦克风结论。
