## 1. 目标与完成后的行为

实现首版**受约束的能力自扩展**：用户描述缺失能力，NEXUS 生成 Tool 或 Skill 候选，自动进行受控检查与测试，展示实际证据；用户批准具体版本后才可使用。之后可复用、查看历史、停用、修订或切回仍符合策略的旧版本。

这是工具代码和任务方法的扩展，不涉及训练模型权重或让模型自动修改系统权限。

| 对象 | 本次范围 | 验收演示 |
| --- | --- | --- |
| Skill | Markdown 说明 + 严格声明式计划，最多 3 个顺序步骤，引用固定版本工具 | “工作区概览”：读取系统信息，再列出 workspace 的直接条目；保留目录审批 |
| Tool | 单个 Python 标准库代码文件，仅处理显式传入的有界 JSON；只在合格沙箱内运行 | “目录条目统计”：统计输入中 file/directory/link/other 数量，不自行读取文件 |
| 组合复用 | 新 Skill 版本在第三步调用已批准的统计 Tool，引用前一步已验证条目 | 显示返回条目统计；输入截断时明确统计不代表整个目录 |

三条演示必须使用真正经过“候选 → 测试 → 批准”的产物，不能只给内置固定工具换一个名字。模拟 Provider 可生成候选代码，只有在实际沙箱执行、返回并被可信控制器比较后，才形成代码执行证据。真实模型生成证据另列，不与替身混淆。

## 3. 必须保持的架构与执行边界

1. Core 继续唯一掌握需求、生成、版本、批准、预算、任务及权威状态；Sandbox Node 是执行身体，不形成第二个规划器、长期记忆或模型调用循环。
2. 复用现有 Harness、策略交集、task/attempt、审计和 model_calls；可以为扩展增加必要记录，不能复制一套独立调度器或费用账本。
3. 默认关闭扩展功能。关闭时 M2/M3、旧协议、旧 Windows Node 和原两个工具保持可用；迁移不得自动启用候选或追溯旧聊天同意。
4. 模型、候选源码、Skill Markdown 和生成测试都是不受信输入。Core 不 import、exec、eval 生成代码，不运行模型生成的验证器、安装脚本或表达式。
5. Tool 不访问真实文件、网络、宿主环境、设备、shell 或其他工具。必要的设备输入由现有可信工具经批准取得，按字段校验后作为 JSON 传入。
6. Skill 只有最多 3 步顺序执行，无循环、任意分支、递归、嵌套 Skill、动态工具名、表达式或模板代码。只允许字面量、已校验用户输入和前面已验证结果的显式字段引用。
7. 版本启用不等于业务执行授权。每步仍检查身份、节点、资源、参数、版本、策略和期限；filesystem.list 的原审批继续有效。用户拒绝或取消时不得自动生成新任务绕过。
8. 不增加 Core/Node 自我重写、自动依赖安装、任意设备读写、Godot 控制、后台自我修复、主动长期目标或自动个人记忆。不为了演示开放通用 Python/shell 工具。

开发所需可信依赖优先复用现有锁定版本；确需新增时说明用途并锁定，不批量升级。安全边界、核心架构或重要依赖方案有实质变化时，先说明具体取舍，遵循 AGENTS 的批准规则。

## 5. 产物、版本、测试和批准

### 5.1 严格且不可变的候选

- manifest 明确 kind、schema_version、能力身份、修订、说明、输入/输出契约、资源/依赖、限制、来源请求和父版本。最终身份与 revision 由 Core 分配/校验，模型不能覆盖内置命名空间或已存在版本。
- Tool 为 manifest、单个源码文本及有限测试；Skill 为 manifest、Markdown 和严格步骤数据。源码与说明只作文本保存/展示；不接受任意压缩包、可执行安装包、远程 URL 或模型指定宿主路径。
- 发布摘要覆盖行为相关的 manifest、源码/说明、步骤、测试、固定依赖、验证配置与环境绑定，排除摘要自身字段，避免自引用。定义规范化规则，拒绝重复 JSON 键、NaN/Infinity、未知字段和歧义编码；结果不能因解析器选择不同而改变含义。
- 依赖固定 revision/摘要；运行镜像固定内容摘要，不使用 latest。修改任何绑定内容均产生新版本及新测试，不能“原地修复”已批准版本。
- 输入/输出 Schema 使用有限、递归有界的子集；拒绝远程引用、任意代码、可执行自定义格式及不受限正则。DSH 在契约中明确允许的关键字、类型和每项限额，用负向测试证明未知关键字不会被忽略。
- 明确候选数量、总存储、版本数、输入深度/数组/字符串及 HTTP 字节上限。沿用架构上界：候选最多 64 KiB、结果最多 32 KiB、测试最多 20 个；所有列表分页，空间满时拒绝新增并保留旧证据，不默默删历史。

### 5.2 独立测试判定

候选不能决定自己是否通过。生成的测试仅为补充，可信控制器负责固定输入、有限断言、实际输出比较、退出状态及限额判断；测试记录绑定产物摘要、控制器/验证配置、环境策略、镜像摘要和实际时间。

Skill 在启用前使用受控工具替身，检查顺序、引用、参数、授权、失败和取消；不得用“测试 Skill”偷偷访问真实设备。生成 Tool 和生成测试代码都必须进入隔离环境，可信控制器不导入候选。对于无法用现有可信断言验证的需求，明确说明验证不足并阻止启用，不能任意采信模型给出的 expected/pass。

至少包含独立的空输入、正常输入、非法类型/字段、超限、错误输出、异常退出、超时及输入提示注入用例。测试通过只证明这些用例和隔离边界；不宣称任何生成代码对所有输入都正确。

### 5.3 两类批准与生命周期

生成、测试、版本可用性及业务执行状态分开存储与呈现。可采用等价的明确状态机，但不能用一个 success 标志概括全部过程。

1. 用户确认本次外发需求，创建稳定 request_id 的扩展请求。
2. 先保存请求及费用预留，再启动一次生成；合法完整候选落盘，尚不可使用。
3. 自动严格检查和受控测试；失败/中断/环境不可用必须显示原因，禁用启用按钮，服务端也拒绝批准。
4. owner 审阅具体版本、差异、测试、费用、权限及运行范围后批准；记录批准人与绑定摘要，幂等提交只生效一次。
5. 批准绑定版本、依赖、测试、验证配置、镜像/环境策略、节点/资源/参数约束和期限。Core 在批准与派发前重查，Node 在实际启动前核对，防止检查和使用之间被替换。
6. 正式任务固定版本，每步再走原业务授权；第一步失败、未知或取消即停止后续步骤。启用不能恢复已取消/过期的任务。
7. 停用原子阻止新派发，在途执行继续受取消/对账约束；明确“停用”与“已停止执行”的差别。切回旧版本也重查当前策略、环境和批准有效性，不回滚历史或费用。
8. 修订必须是用户明确的新请求，引用父版本并重新测试、审阅、批准。失败只提出建议，不自动消耗模型调用或覆盖旧版本。

具体批准与执行期限由 DSH 固化进契约和说明；不得永久继承一次批准，也不得以变更任务 ID、节点或参数规避绑定。

## 6. 模型、外发与聊天衔接

| 项目 | 必须保持的限制 |
| --- | --- |
| 费用账本 | 复用全局 model_calls，UTC 日 USD 1、每日最多 100 次、每根扩展请求 USD 0.05；与 M2/M3 原子共享额度和全局单并发 |
| 生成 | 每根扩展请求最多一次调用，30 秒，无自动重试/修复/续写；4096 输出 token 独立配置，默认禁用生成，不放宽 M2 的 512 或 M3 的 2048 |
| 输入与产物 | 按架构的 16384 输入 token 费用边界、HTTP 请求 32 KiB、响应/候选 64 KiB 实际检查；输出截断、缺失用量与非法候选如实结算和失败 |
| 未知成本 | 超时、停止、断流、崩溃不能释放未知预留；跨日保留，重启不重发；价格过期、暂停或账本写入失败阻止新调用 |
| 基础工作 | 能力查询、摘要、心跳、重连、测试调度、执行恢复、结构化汇总、停用/回退不调用模型 |

每次生成前展示真正将外发的内容，默认仅当前需求、公共产物契约和已获准的最小工具描述。设备结果、聊天历史、个人记忆、路径、凭证、旧代码或失败样本不因创建扩展自动发送；若修订需要旧代码/样本，逐次预览并保存具体同意。

聊天可以发现能力缺口，提供带需求草稿的“创建能力”入口；讨论或模型的文字建议不等于同意外发与生成。已有原请求用过一次模型时仅登记缺口，用户明确新建扩展请求后才生成；不能悄悄拆子任务重置调用额度。扩展请求、生成、批准和业务执行的关联可追踪，不能混用 request_id、revision、task_id 或 attempt_id。

首版通过“能力”入口显式选择已启用版本使用；不要求把所有生成产物直接塞入现有聊天函数列表。M3 的固定两工具确认、自动回传勾选和每轮最多两次调用继续工作。新 Tool/Skill 结果默认结构化显示，不继承 M3 两个工具的外发白名单，也不为“显得智能”增加总结调用；未来若接入模型需独立定义字段及同意。

现有价格快照有效期记录截至 2026-10-25 UTC 当日。执行时读取实际配置；过期则阻止真实调用并人工核对，不能修改日期或抬高预算来让测试通过。

## 7. Sandbox Node 与协议

### 7.1 环境门槛

沿用架构建议：独立 Linux 执行环境、Sandbox Node、gVisor runsc、固定摘要的 Python 标准库镜像。优先与权威 Core 不同的执行主机。当前交接**没有已验证的专用沙箱主机或镜像**，也没有批准新增主机费用或改造生产 Core 宿主。

DSH 在已获准的专用环境核对内核、运行时、宿主 cgroup、用户/挂载/网络隔离、镜像和进程清理。需要安装或新资源时提交具体需求；可以继续其他开发，但不得退回普通 subprocess、Docker 默认运行时、Windows Job、受限 import 或 Python 审计钩子冒充代码沙箱。用替身验证错误路径不构成 runsc 隔离实测。

测试和正式 JSON Tool 使用相同镜像及策略配置；每次新建短生命周期沙箱。至少验证：

- 无外部网络、云元数据、宿主文件/设备/控制 socket 和环境秘密；只提供固定只读运行文件、该次候选与 JSON 输入。Node 凭证和 Core 数据库永不进入沙箱。
- 非特权执行，不使用 privileged/host network 或模型提供的 OCI 参数、命令行、挂载位置；固定可信入口读取有界 JSON，候选不能选择宿主可执行程序。
- 宿主实际强制 CPU、内存、PID、临时存储与墙钟限额；按架构上界每环境并发 1、1 vCPU、512 MiB、64 进程、16 MiB 临时空间、每工具 10 秒、整个测试 60 秒，stdout 最多 32 KiB，诊断另设有限上限。若平台只能提供不同的保证，列差异并在采用前确认，不能宣称已等价。
- 超时、取消、输出/内存/PID 爆发、Node 异常退出后，实际执行被终止或明确 unknown，不能只取消等待协程。确认旧沙箱停止前占用执行槽，不新建重复执行。

隔离的证明要给出实际运行时/镜像/宿主配置和受控负向测试；不能仅展示一份配置文件或候选自己打印的“访问失败”。不对生产机做逃逸/破坏性试验。

### 7.2 协议和回执

先写具体协议规格，再实现：采用显式协商的新扩展主版本/独立入口，保留 v1；未知版本、未知字段或无协商时拒绝。新命令绑定 capability_id、revision、产物/环境/验证摘要、步骤、参数、任务/尝试、授权及期限。不能把任意源码塞进原 v1 tool 字符串或放宽其严格解析。

产物由系统生成地址/标识，经认证、有界、按摘要传输并核验；不让 Node 下载模型提供的 URL。旧 Windows Node 继续只执行 v1 两个工具；Skill 的旧工具步骤仍走原链路，JSON Tool 仅派发给具备新协议且登记授权的 Sandbox Node。Core 配置、已认证能力与 Node 本地策略取交集，不因 Node 自报而授予权限。

Node 在开始前持久化回执，结果持久化后回传；Core 落盘后才 ack。重复相同 attempt 只对账/返回原结果，不重跑；同 ID 不同摘要拒绝。重启区分未开始、执行中、已完成和未知，生成 Tool 首版不自动创建新尝试。Skill 已完成步骤不重跑，剩余步骤每次派发重查批准和停用状态，总期限最多 5 分钟。
