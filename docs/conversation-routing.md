# 对话检索与会话路由

聊天开启工具并同意本轮结果外发后，可以直接问：

- “昨天那个手势功能做完了吗？”
- “今天都做了什么？”
- “游戏项目现在完成到哪了？”
- “打开刚才提到的那个会话。”

Core 从本人原始聊天、关联任务和项目待办检索资料，模型据此整理回答。相关会话以来源卡片显示；点击可打开。只有明确要求打开且目标清楚时，发起这轮文字请求的客户端才自动切换一次。其他客户端、历史重载和应用重启不会重放跳转。不发送消息给旧会话，不恢复归档，不继续执行旧任务。

网页、Windows 和 Android 分别保留各会话的文字草稿。网页有未发送附件时会要求先发送或移除，防止切换丢失附件。Android 保留加密草稿；APK 升级不需要卸载旧版。

## 查询与证据

`conversation_route` 是现有聊天工作流程中的 Core 只读工具，沿用 owner、工作授权、结果外发、取消和审计。它不要求设备在线执行，但当前工作目录仍依赖已有设备登记和工作授权；不创建第二个模型循环或长期记忆库。

| 操作 | 行为 |
| --- | --- |
| `search` | 用简短关键词、项目、日期寻找原始轮次；关键词在分页前匹配，可发现超过最近200条的旧热记录 |
| `read` | 按已发现的 `conversation_id` 查看该会话最新轮次；核对昨天的功能时，应取消昨天的日期条件再查最新结果 |
| `project` | 项目名或编号对应的任务状态/验证级别统计、最近待办及会话；同名或模糊匹配有多个结果时先确定目标 |
| `open` | 生成由 Core 核对归属的来源和客户端导航请求；模型文字或自造链接不能变成跳转 |

`period=today/yesterday` 固定按北京时间，显式 `date_from/date_until` 使用 `YYYY-MM-DD`，结束日期不包含在内。默认不查归档；`include_archived=true` 会核验并读取冷归档，不解档。结果包含观察时间、截断说明和 `next_before`；摘要不是全天的完整统计，必要时继续分页。

聊天回复结束、待办标记 done 与功能验收是不同事实。回答须保留任务 `status`、`execution_outcome`、`verification` 和未停止尝试；没有执行证据时只能报告聊天中的说法。项目里未登记的工作不在统计内。

检索仅限当前 owner；不会外发携带显式记忆引用、资料引用或附件的旧轮次，也不会读取失效自动记忆轮次的正文。活动/恢复中的轮次只返回有限状态，不将部分回复作为最终结果。检索所得轮次继承来源自动记忆策略修订与最早有效期，撤权后不能通过派生回答绕过。含本工具的派生回答不再作为原始搜索命中，避免递归引用。

## 接口接入

`turn.presentation` 兼容新增 `conversations[]` 和可空 `navigation`。来源含会话编号、标题、项目名、可选轮次编号、记录时间和归档状态；导航含 `step_id/conversation_id`。客户端用正常认证接口打开目标，不能把卡片内容当 HTML；显示卡片不更改目标会话。

自动跳转必须同时满足：本客户端本次提交的 `request_id`、`presentation.phase=completed`、未消费的 `step_id`。导航消费标记不从历史恢复；切换中迟到的历史请求不得覆盖当前会话。失败保留来源按钮供手动重试。

实现、验证与发布状态统一见 [P96](ROADMAP.md#p96-conversation-routing)。
