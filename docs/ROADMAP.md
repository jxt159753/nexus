M 表示面向用户的一组产品能力；S 表示内部开发子阶段；P 表示具体任务。M1 的 S1 只是一项工程准备，不等于整个 M1。

| 里程碑 | 用户能获得什么 | 当前状态 |
| --- | --- | --- |
| M1 可靠执行基础 | 手机或电脑提交只读任务，审批、执行、查结果，断线后可恢复 | **已验收**；用户于 2026-10-18 明确确认 |
| M2 自然语言任务 | 把一句请求解释成已有工具动作，确认后执行 | **已上线，技术交付完成，待最终用户验收** |
| M3 聊天与工具结果 | 连续聊天、管理会话、确认工具、同意回传后生成最终回答 | **已上线，待真机补验及最终用户验收** |
| M4 自定义工具与流程 | 生成、测试、逐版批准并复用新的 Tool/Skill | **功能及隔离/恢复已部署验证；真实生成 Tool 已批准启用；Android 细节及最终用户验收待确认** |
| M5 从聊天完成多步任务 | 直接说出目标，核对有限计划后复用已启用能力完成任务 | **实现与获批上线完成；具体 Skill 批准启用、真实模型/新版沙箱组合、Android 及最终验收待补** |
| M6 项目与可控记忆 | 项目内会话与进展、逐轮选定记忆、可追溯待办、基础工具及会话工作 | **已部署、技术验证完成；新链路真实模型/Android 真机及最终用户验收待补** |
| M7 提醒与周期任务 | 在明确时间和范围内提醒或检查，随时可暂停 | **远期方向，未批准实施** |

建议顺序：补齐 M4 → M5 → M6 → 按需求决定 M7/M8。M2/M3 的用户验收单独补齐，不因为进入其他工作就自动变为“已验收”。不为尚未确认的范围承诺日期。

Web 前端完善随相关功能一起交付，不能等全部后端做完才补界面。M8A 的 App 控制台只依赖选定 Core 接口稳定，可单独提前批准，与 M5/M6 协调开发，不强制等待 M7 或 Android 执行端完成。具体安排见 [前端与 App 开发](#前端与-app-开发)。

### 会话命名与聊天工具

首轮同一次回复生成标题；模型最多建议一个原有只读动作，用户确认后才能创建任务。目录仍需原审批。证据见 [会话工具验证](assets/chat-tools-evidence.json)，设计见 [ADR 0011](decisions/0011-chat-titles-actions.md)。

<a id="12-m3-补充工具结果回传与最终回答"></a>

### 工具结果回传

工具实际成功后可选择白名单字段、预览并同意发送，再生成最终回答。普通聊天一次调用，含结果解读最多两次，合计共用本轮 USD 0.05。证据见 [结果回传验证](assets/chat-results-evidence.json)，设计见 [ADR 0012](decisions/0012-chat-result-feedback.md)。

<a id="13-m3-补充确认工具时同意自动回传"></a>

### 提前同意，成功后自动回答

工具确认卡可逐次勾选本次有限结果回传，成功后自动回答；默认不勾选，旧记录不自动补发。真实系统工具、自动回答和紧接着的“信息是啥”追问已有技术证据；见 [自动回传验证](assets/chat-auto-results-evidence.json)和 [ADR 0013](decisions/0013-chat-auto-result-consent.md)。

剩余验收：最新版本的 Android 真机连续聊天、停止与刷新历史，以及真实目录结果总结。调用后的在线一致快照已有记录，不能当作这一版本额外生产重启已验证。用户最终验收仍待确认；使用见 [聊天说明](m3-chat.md)。

### M7：提醒与周期任务

远期目标：在用户指定的时间和范围内做提醒或有限检查，减少需要反复手动发起的工作。

建议先做控制台内提醒和固定只读检查，再考虑有限的目标跟进。时间、时区、截止条件、次数、费用和可用工具要明确；重启不能重复触发，离线补执行规则应可理解。

验收示例：设置“每个工作日 18:00 提醒我查看项目待办”，能查看下次时间、暂停、修改和取消；没有提醒时不调用模型，超出范围的事情先停下。对外消息渠道、全天后台推理和无期限自主执行不包含在默认范围内。任务编号在方向批准后再细化。
